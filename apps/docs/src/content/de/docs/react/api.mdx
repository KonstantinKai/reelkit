## Observer-Komponenten [#observer-components]

### Observe [#observe]

Verbindet die Signals aus dem Core mit dem Rendern in React, ohne das Elternelement neu zu rendern. Nur die Funktion in children läuft erneut, wenn sich abonnierte Signals ändern.

<CodeBlock code={observe} language="tsx" />

| Prop | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `signals` | `Subscribable[]` | `required` | Signals, die abonniert werden. Meldet sich eines davon, läuft die Funktion in children erneut – und nur diese, nie das Elternelement. Ein anderes Signal bei einem späteren Render wird an Stelle des ersetzten verfolgt. |
| `children` | `() => ReactElement \| null` | `required` | Render-Funktion, die bei jeder Änderung erneut läuft. Lies die Werte der Signals darin; ein außerhalb gelesener Wert wird einmal festgehalten und veraltet. |

### AnimatedObserve [#animatedobserve]

Abonniert Signals mit animierten Werten und interpoliert sie weich per `requestAnimationFrame`.

<CodeBlock code={animatedobserve} language="tsx" />

| Prop | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `signal` | `Signal<AnimatedValue>` | `required` | Signal, das \{ value, duration, done? \} ausgibt. Eine Dauer über 0 interpoliert vom aktuellen Wert zum neuen; bei 0 springt der Wert direkt dorthin. |
| `children` | `(value: number) => ReactElement` | `required` | Render-Funktion, die den interpolierten Wert für den aktuellen Frame bekommt. Er wird synchron übernommen, damit das DOM mit der Animation Schritt hält. |

## SwipeToClose [#swipetoclose]

`<SwipeToClose>` legt seine Kinder in einen Container, der einem vertikalen Wischen folgt und `onClose` aufruft, sobald das Wischen die Schwelle überschreitet — die Geste zum Schließen der Lightbox und des Stories Player, für ein eigenes Overlay. `SwipeToCloseProps` typisiert seine Props; `SwipeToCloseDirection` ist `'up' | 'down'`.

| Prop | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `direction` | `SwipeToCloseDirection` | Pflicht | `'up'` schließt wie die Lightbox, `'down'` wie der Stories Player |
| `onClose` | `() => void` | Pflicht | Wird aufgerufen, nachdem das Wischen die Schwelle überschritten hat und die Animation zum Schließen endet |
| `enabled` | `boolean` | `true` | Schaltet die Geste ab, ohne auszuhängen |
| `threshold` | `number` | `0.2` | Anteil der Höhe des Viewports, den das Wischen zurücklegen muss |
| `className` | `string` | — | Klasse am äußeren `<div>` |
| `children` | `ReactNode` | Pflicht | Inhalt, der sich mit dem Wischen bewegt |

## SoundProvider [#soundprovider]

`<SoundProvider>` erstellt einen `SoundController`, anfangs stumm, und reicht ihn über `useSoundState` an seine Kinder weiter. Die Overlays rendern selbst einen; füge deinen eigenen nur um einen eigenen Player hinzu, dessen Bedienelemente sich eine Stummschaltung teilen.

### useOverlayUrlState [#useoverlayurlstate]

<Caption>`OverlayUrlStateOptions`</Caption>

Baut einen URL-State-Controller für ein Overlay, den du einem `*UrlOverlay` als Prop `controller` übergibst.

Eine Schritt-für-Schritt-Erklärung und Beispiele findest du unter [URL-State im React-Leitfaden](/docs/react/guide#url-state).

| Option | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `param` | `string` | Pflicht | Query-Parameter, der den aktiven Slide trägt, zum Beispiel "photo". Wird beim ersten Render gelesen und bleibt für die Lebensdauer der Komponente fest – zum Ändern neu mounten (gib ihr einen key). |
| `adapter` | `UrlAdapter` | History API | Navigationssystem, über das gelesen und geschrieben wird. Übergib in einer App mit Router einen Adapter auf Basis des Routers, damit die Location des Routers nicht veraltet. Wird beim ersten Render gelesen und bleibt für die Lebensdauer der Komponente fest – zum Ändern neu mounten. |
| `codec` | `{ decode(raw) => Id \| null; encode(id) => string }` | Pflicht | Format in der URL: Text des Parameters ↔ eine stabile Identität, unabhängig von der Sammlung. Reist mit locator als zusammengehöriges Paar mit demselben Id – spreize ...urlIndexKey(() => images.length) für die Standardgalerie mit Index ?photo=3, oder bring einen eigenen mit (base64, slug), damit ein Lesezeichen das Umsortieren der Galerie übersteht. Wird live gelesen: Der codec des letzten Renders übernimmt das nächste Decodieren oder Encodieren. |
| `locator` | `{ locate(id) => number \| null; locateAsync?(id) => Promise<number \| null>; identify(index) => id }` | Pflicht | Bildet die Identität auf eine Position ab und prüft ihre Gültigkeit selbst: locate (synchron), locateAsync (asynchroner Fallback für eine Galerie mit Paginierung), identify (Schreiben). Für eine einfache Galerie mit Index spreizt du ...urlIndexKey(() => images.length) – es liefert diesen locator plus den passenden codec und begrenzt ?photo=3 mit der aktuellen Anzahl, sodass ein veraltetes ?photo=99 von selbst aus der URL verschwindet, statt einen Slide zu öffnen, den nie jemand gemeint hat. Ein Feed mit Paginierung oder eine Galerie mit Schlüsseln nach Identität bringt stattdessen ein eigenes passendes Paar aus codec + locator mit. Wird live gelesen: Der locator des letzten Renders beantwortet die nächste Suche, und wird locateAsync zwischen zwei Renders hinzugefügt oder entfernt, wirkt das beim nächsten Fehlschlag. |

### useReactRouterUrlAdapter [#usereactrouterurladapter]

Ein `UrlAdapter` auf Basis von React Router. Übergib ihn in einer App mit Router als Option `adapter` an `useOverlayUrlState`, damit der Router die einzige Quelle der Wahrheit für die Navigation bleibt – wer am Router vorbei `history.pushState` schreibt, lässt seine Location veralten, und die nächste Navigation verliert den Parameter. Geschrieben wird nur die Query, Pfad und Hash bleiben also unberührt. Jede Änderung meldet, ob der Router auf derselben Seite einen Eintrag angelegt, ersetzt oder sich durch den Verlauf bewegt hat, sodass eine aus einem `<Link>` geöffnete Galerie mit einem Schritt zurück schließt.

Kommt aus einem eigenen Subpfad, damit eine App ohne Router nie `react-router-dom` in ihr Bundle zieht. `react-router-dom` ist eine optionale Peer-Abhängigkeit.

### useReelContext [#usereelcontext]

`useReelContext()` liest den `ReelContextValue` des nächsten übergeordneten `<Reel>` oder gibt außerhalb davon `null` zurück. `<ReelIndicator>` verbindet sich darüber selbst; nutze es in deinen eigenen Bedienelementen, die du als Kinder von `<Reel>` renderst, damit sie dem Slider ohne Props folgen. `ReelContext` ist das Context-Objekt dahinter — stelle nur in einem Test oder einem eigenen Wrapper einen eigenen Wert bereit.

| Eigenschaft | Typ | Beschreibung |
| --- | --- | --- |
| `index` | `Signal<number>` | Index des aktiven Slides; lies `.value` innerhalb von `Observe` |
| `count` | `Signal<number>` | Gesamtzahl der Slides |
| `goTo` | `(index: number, animate?: boolean) => Promise<void>` | Geht zu einem Slide, animiert oder nicht |

### useSoundState [#usesoundstate]

`useSoundState()` liest den `SoundController` aus dem nächsten `<SoundProvider>` und wirft außerhalb davon einen Fehler. Der Reel Player, die Lightbox und der Stories Player legen einen Provider um ihren Inhalt, sodass eigene Bedienelemente, die du über ihre Render-Props übergibst, damit die Stummschaltung lesen oder umschalten können.

### useFullscreen [#usefullscreen]

`useFullscreen({ ref })` steuert die Fullscreen-API für das Element in `ref` und beendet das Vollbild, wenn die Komponente ausgehängt wird. `UseFullscreenProps` ist sein Argument; `UseFullscreenResult` ist das Tupel, das es zurückgibt.

| Index | Typ | Beschreibung |
| --- | --- | --- |
| `[0]` | `Signal<boolean>` | Ob die Seite im Vollbild ist; lies `.value` innerhalb von `Observe` |
| `[1]` | `() => Promise<void>` | Fordert das Vollbild für das Element an und verlässt vorher ein anderes Element im Vollbild |
| `[2]` | `() => Promise<void>` | Beendet das Vollbild |
| `[3]` | `() => Promise<void>` | Wechselt zwischen beidem |

## Barrierefreiheit [#accessibility]

`<Reel>` rendert als `role="region"` mit `aria-roledescription="carousel"`. Setze das Prop `ariaLabel`, um der Region einen Namen für Screenreader zu geben. Eine höfliche Live-Region kündigt bei jedem Slide-Wechsel "Slide N von M" an, ohne das Karussell neu zu rendern. Inaktive Slides bekommen das Attribut `inert`, damit Fokus und Navigation von Hilfstechnologien sie überspringen.

`<ReelIndicator>` rendert als `role="tablist"` mit wanderndem tabindex auf den Punkten; die Pfeiltasten bewegen den Fokus, und Enter oder Leertaste aktivieren den Slide.

Du baust ein eigenes Modal um `<Reel>`? `captureFocusForReturn`, `createFocusTrap` und `getFocusableElements` werden aus `@reelkit/react` erneut exportiert, für die Rückgabe und das Einsperren des Fokus.

Siehe [Autoplay](/docs/core/api#autoplay) und [Download](/docs/core/api#download) in der Core-API.
