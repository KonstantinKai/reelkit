## URL-State [#url-state]

`useOverlayUrlState` baut einen URL-State-Controller für ein Overlay und gibt ihn vollständig zurück; den übergibst du einem `<LightboxUrlOverlay>` als Prop `:controller`. Die Adressleiste bestimmt, ob es offen ist, also öffnet sich ein gebundenes Overlay selbst, und ein Link ist die übliche Aktion zum Öffnen. Der erste Schreibvorgang eines fehlenden Parameters legt einen Eintrag im Verlauf an, jeder weitere ersetzt ihn, sodass das Blättern den Zurück-Button nie verschüttet. Behalte den Controller, um `value`/`position` zu lesen und per `set(null)` im Code zu schließen — derselbe einfache Schreibvorgang, den das Overlay intern beim Wechsel des Slides nutzt.

<CodeBlock code={urlState} language="vue" />

Das Optionsobjekt nimmt `param`, `codec` und `locator` (alle drei Pflicht) sowie einen optionalen `adapter`. `codec` und `locator` sind ein zusammengehöriges Paar mit demselben `Id`, also verteilst du für eine einfache Galerie mit `?photo=3` einfach `...urlIndexKey(() => props.images.length)`, das beide Hälften auf einmal liefert. `urlIndexKey` bildet den Parameter auf einen Slide-Index ab und prüft ihn gegen die aktuelle Anzahl, die der Getter liefert. Ein veraltetes oder zu großes `?photo=99` wird so abgelehnt und verschwindet von selbst aus der URL, statt einen Slide zu öffnen, den nie jemand gemeint hat. Übergib einen Getter, keine Zahl: Ein `setup` in Vue läuft nur einmal, eine dort festgehaltene Länge veraltet also, sobald ein seitenweise geladener Feed wächst. Es umschließt `createIndexLocator` (die Locator-Hälfte) und kombiniert es mit `indexCodec`. Ein seitenweise geladener Feed oder eine Galerie mit Schlüsseln nach Identität liefert stattdessen ein eigenes Paar aus `codec` + `locator`. Die vollständige Tabelle der Optionen steht in der [Vue-API-Referenz](/docs/vue/api#useoverlayurlstate).

## Das Wichtigste [#key-points]

<KeyPoints>
<KeyPoint title="Composition API">
  Importiere `Reel`, `ReelIndicator` und die Composables direkt in dein `<script setup>` — eine Plugin-Registrierung ist nicht nötig
</KeyPoint>
<KeyPoint title="Scoped Slot #item">
  Das Vue-Gegenstück zum Prop `itemBuilder` aus React — Virtualisierung mit vertrauter Template-Syntax
</KeyPoint>
<KeyPoint title="Template-Ref">
  Nutze `ref<ReelExpose>()` für die imperative Navigation — Event-Callbacks sind dafür nicht nötig
</KeyPoint>
<KeyPoint title="@after-change">
  Sendet `(index, rangeIndex)` — verfolge den aktuellen Index für Updates der Oberfläche
</KeyPoint>
<KeyPoint title="Kontext über provide/inject">
  `ReelIndicator` verbindet sich über provide/inject von Vue selbst mit dem umgebenden `Reel` — kein Durchreichen von Props von Hand
</KeyPoint>
</KeyPoints>

## Tipps zur Performance [#performance-tips]

<KeyPoints>
<KeyPoint title="Halte die Slide-Templates schlank">
  Der Slot `#item` läuft für jeden sichtbaren Slide (meist 3 gleichzeitig). Vermeide darin aufwendige Berechnungen oder tief verschachtelte Strukturen.
</KeyPoint>
<KeyPoint title="Lade Daten kurz vor dem Ende">
  Erkenne mit `@after-change`, wann sich der Nutzer dem Ende nähert, und lade den nächsten Schwung, bevor die Slides ausgehen — so entstehen endlos scrollende Feeds.
</KeyPoint>
<KeyPoint title="Nutze Refs für den imperativen Zustand">
  Lege die Referenz auf `ReelExpose` und den aktuellen Index in `ref()`s von Vue ab, für feingranulare Reaktivität ohne unnötige Re-Renders.
</KeyPoint>
<KeyPoint title="Schalte das Mausrad auf scrollbaren Seiten ab">
  Setze `:enable-wheel="false"`, wenn der Slider in einem scrollbaren Layout steckt, damit er das Scrollen der Seite nicht abfängt.
</KeyPoint>
</KeyPoints>
