### useOverlayUrlState [#useoverlayurlstate]

<Caption>`OverlayUrlStateOptions`</Caption>

Baut einen URL-State-Controller für ein Overlay, den du einem `<LightboxUrlOverlay>` als Prop `:controller` übergibst.

Den Ablauf und Beispiele findest du unter [URL-State im Vue-Leitfaden](/docs/vue/guide#url-state).

| Option | Typ | Standard | Beschreibung |
| --- | --- | --- | --- |
| `param` | `string` | Pflicht | Query-Parameter, der den aktiven Slide trägt, zum Beispiel "photo". |
| `adapter` | `UrlAdapter` | History API | Das Navigationssystem, über das gelesen und geschrieben wird. Übergib in einer App mit Router einen Adapter auf Basis des Routers, damit dessen eigene Location nicht veraltet. |
| `codec` | `{ decode(raw) => Id \| null; encode(id) => string }` | Pflicht | Format auf der Leitung: Parametertext ↔ eine stabile Identität, ohne Wissen über die Sammlung. Bildet mit locator ein zusammengehöriges Paar mit demselben Id — verteile ...urlIndexKey(() => props.images.length) für die Standardgalerie mit Index wie ?photo=3, oder liefere ein eigenes (base64, Slug), damit ein Lesezeichen eine neu sortierte Galerie übersteht. |
| `locator` | `{ locate(id) => number \| null; locateAsync?(id) => Promise<number \| null>; identify(index) => id }` | Pflicht | Bildet die Identität auf eine Position ab und ist selbst für deren Gültigkeit zuständig: locate (synchron), locateAsync (asynchroner Rückfall für eine seitenweise geladene Galerie), identify (Schreiben). Für eine einfache Galerie mit Index verteilst du ...urlIndexKey(() => props.images.length) — das liefert diesen Locator samt passendem Codec und prüft ?photo=3 gegen die aktuelle Anzahl, sodass ein veraltetes ?photo=99 aus der URL verschwindet, statt einen Slide zu öffnen, den nie jemand gemeint hat. Übergib einen Getter, keine Zahl, denn ein setup in Vue läuft nur einmal, und eine dort festgehaltene Länge veraltet, sobald ein seitenweise geladener Feed wächst. Ein seitenweise geladener Feed oder eine Galerie mit Schlüsseln nach Identität liefert stattdessen ein eigenes Paar aus codec + locator. |

### useVueRouterUrlAdapter [#usevuerouterurladapter]

Ein `UrlAdapter` auf Basis von Vue Router. Übergib ihn in einer App mit Router als Option `adapter` an `useOverlayUrlState`, damit der Router die einzige Quelle der Wahrheit für die Navigation bleibt — wer `history.pushState` am Router vorbei schreibt, lässt dessen Location veralten, und die nächste Navigation verliert den Parameter. Geschrieben wird nur in die Query, also bleiben Pfad, Hash und wiederholte Schlüssel wie `?tag=a&tag=b` unberührt. Jede Änderung meldet, ob der Router auf derselben Seite einen Eintrag angelegt, ersetzt oder im Verlauf geblättert hat, sodass eine aus einem `<router-link>` geöffnete Galerie mit einem Schritt zurück schließt.

Er kommt aus einem eigenen Unterpfad, sodass eine App ohne Router `vue-router` nie in ihr Bundle zieht. `vue-router` ist eine optionale Peer-Abhängigkeit ab Version 4.1: Der Adapter trägt seinen Besitzstempel über die Navigationsoption `state` des Routers, die ältere Versionen ignorieren. Mit einem älteren Router bricht nichts — das Schließen entfernt den Parameter dann nur an Ort und Stelle, statt einen Schritt zurückzugehen.

### toVueRef [#tovueref]

Verbindet ein `Subscribable` aus dem Core (jedes `Signal` aus `@reelkit/core`) mit einem schreibgeschützten `Ref` von Vue. Nutze es immer dann, wenn der Wert eines Core-Signals ein Re-Render in Vue auslösen soll — ein direktes Lesen von `signal.value` in Render-Funktionen oder Templates ist für sich allein **nicht** reaktiv.

Das Abonnement wird über `onScopeDispose` automatisch aufgeräumt, darum muss es innerhalb von `setup()` in Vue oder einem anderen Kontext mit Effect-Scope aufgerufen werden.

## Observe [#observe]

Tag: `<Observe :signals="[…]">` — rendert seinen Default-Slot neu, sobald sich eines der Signale ändert, und sonst nichts darum herum.

Das Lesen eines Core-Signals in einer Render-Funktion oder einem Template abonniert es nicht. [`toVueRef`](#tovueref) ist die übliche Antwort, bindet das Signal aber an die Komponente, die es aufruft; ein Signal, das sich oft ändert, rendert also die ganze Komponente neu. `Observe` ist die engere Grenze: Lege es um den Teil, der den Wert zeigt, und der Rest der Komponente bleibt, wie er ist. So zeichnet der Stories Player seinen Header und seinen Fortschrittsbalken neu, ohne einen der beiden Slider neu zu zeichnen.

| Prop | Typ | Beschreibung |
| --- | --- | --- |
| `signals` | `readonly Subscribable[]` | Die Signale, denen gefolgt wird. Eine andere Menge tauscht das Abonnement aus, dieselbe Menge behält es. Beim Unmount wird alles freigegeben. |

Der Typ der Props wird als `ObserveProps` exportiert.

<CodeBlock code={observe} language="vue" />

Greif zu `toVueRef`, wenn die ganze Komponente dem Signal folgt, und zu `Observe`, wenn das nur ein Bereich davon tut.

## asGenericPropKeys [#asgenericpropkeys]

Baut eine Komponente, die generisch über die Elemente ist, die sie bekommt, so wie `ReelPlayerOverlay` und `StoriesOverlay`. Vue 3.3 akzeptiert eine Setup-Funktion mit Typparameter, `defineComponent(<T>(props: Props<T>) => …, options)`, behält diesen Parameter aber nur, wenn `options.props` Namen von Props auflistet. Übergibst du ein Props-Objekt, liest Vue die Typen der Props aus dem Objekt zurück, und `T` geht verloren. `asGenericPropKeys` reicht das Props-Objekt unverändert durch, während der Typchecker eine Liste von Namen sieht: `T` wird aus dem abgeleitet, was die Elternkomponente bindet, und Standardwerte, Validierung und die Umwandlung in Boolean greifen zur Laufzeit weiterhin.

Das Typargument ist der Props-Typ mit dem Basiselement, und die Komponente braucht Vue 3.3 oder neuer. Slots und Emits können `T` nicht nutzen: Typisiere einen Slot-Scope, indem du ihn im Template annotierst.

## Barrierefreiheit [#accessibility]

`<Reel>` wird als `role="region"` mit `aria-roledescription="carousel"` gerendert. Übergib `aria-label` (in TS heißt das Prop `ariaLabel`), um der Region einen Namen für Screenreader zu geben. Eine höfliche Live-Region kündigt bei jedem Wechsel "Slide N of M" an. Inaktive Slides bekommen das Attribut `inert`, damit Fokus und Navigation mit Hilfstechnik sie überspringen.

`<ReelIndicator>` wird als `role="tablist"` gerendert, mit wanderndem Tabindex auf den Punkten; die Pfeiltasten bewegen den Fokus, und Enter oder Leertaste aktivieren den Slide.

Baust du ein eigenes Modal um `<Reel>`? `captureFocusForReturn`, `createFocusTrap` und `getFocusableElements` werden aus `@reelkit/vue` erneut exportiert, für die Rückgabe des Fokus und die Fokusfalle.
