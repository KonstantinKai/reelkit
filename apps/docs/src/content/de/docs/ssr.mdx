Alle Pakete von reelkit laufen auf dem Server. Du kannst sie mit Next.js, Remix, Angular SSR, Nuxt 3 oder jedem anderen SSR-Setup importieren und rendern.

## So funktioniert es [#how-it-works]

Der Slider-Controller im Core ist reine Logik und greift beim Erstellen nicht auf das DOM zu. Gesten-Listener, Tastatur-Events und Animationen werden erst in den Lifecycle-Hooks auf dem Client angehängt.

<FrameworkVariant for="react">

Beim SSR rendert `Reel` für React einen statischen Container mit den anfangs sichtbaren Slides (meist 3: vorheriger, aktueller, nächster), wenn es ein `size` hat, und einen leeren Container, wenn es sich selbst misst. Bei der Hydration hängt es die Controller für Gesten, Tastatur und Mausrad an und macht damit alles interaktiv.

</FrameworkVariant>

<FrameworkVariant for="vue">

`Reel` für Vue rendert auf dem Server einen leeren Container und zeichnet seine Slides erst nach der Hydration. Mit einer `size` passt dieser Container nicht zu dem, was der Client zuerst rendert. In Nuxt gehört es dann in `<ClientOnly>` (siehe [Nuxt 3](#nuxt-3)).

</FrameworkVariant>

## Responsive Größe mit SSR [#responsive-size-with-ssr]

Lass das Prop `size` ganz weg. Ohne `size` misst Reel seinen Container auf dem Client selbst über `ResizeObserver`. Beim SSR rendert der Slider einen leeren Container; bei der Hydration misst er und rendert die Slides sofort:

<CodeBlock code={nextAutoSize} language="tsx" />

<Callout type="info" title="So funktioniert die automatische Größe">
  Ohne `size` muss die Größe des Containers per CSS festgelegt sein (Flex- oder Grid-Elternelement, feste Breite und Höhe oder Prozentwerte). Der Slider rendert nichts, bis die erste Messung fertig ist, füllt danach die gemessene Fläche und reagiert auch auf spätere Größenänderungen automatisch.
</Callout>

### Feste Größe (manueller Weg) [#explicit-size-manual-approach]

Für Kontrolle auf den Pixel genau übergibst du ein festes Prop `size`. Da `window.innerWidth` beim SSR nicht verfügbar ist, gib einen Standardwert vor und aktualisiere ihn beim Mounten:

<CodeBlock code={nextExplicitSize} language="tsx" />

<Callout type="info" title="Tipp">
  Wähle als Standard die Größe, die zu deinem häufigsten Viewport passt (zum Beispiel Mobile First). Weicht der tatsächliche Viewport ab, passt sich der Slider bei der Hydration sofort an.
</Callout>

## Nuxt 3 [#nuxt-3]

Die Vue-Komponenten von ReelKit lassen sich ohne Fehler auf dem Server importieren und rendern. `Reel` schickt vom Server einen leeren Container und zeichnet seine Slides erst nach der Hydration. Wenn sich `Reel` selbst misst, wird dieser Container ab `@reelkit/vue` 0.9.1 ohne Abweichung hydriert; in früheren Versionen hatte er keine Höhe, sodass keine Slides erschienen. Mit einer festen `size` enthält schon der erste Render auf dem Client Slides, und das ergibt eine Abweichung bei der Hydration. In diesem Fall oder mit einer früheren Version umschließe `Reel` mit einer Komponente `<ClientOnly>` oder verwende die Endung `.client.vue`:

## Responsive Größe mit SSR [#responsive-size-with-ssr]

Lass das Prop `size` weg, um die automatische Messung zu nutzen. Reel nimmt dann 100 % seines Elternelements ein und braucht ab `@reelkit/vue` 0.9.1 kein `<ClientOnly>`: Der Server schickt einen leeren Container in voller Größe, und der Client misst ihn und rendert die Slides. ## Overlay-Komponenten [#overlay-components]

`ReelPlayerOverlay`, `LightboxOverlay` und `StoriesOverlay` rendern nichts, solange `isOpen` false ist. Sie brauchen daher kein `<ClientOnly>` und erzeugen beim Server-Rendering kein Markup. Ihren Inhalt teleportieren sie erst in den Body, wenn sie auf dem Client geöffnet werden.

</FrameworkVariant>

## Zusammenfassung [#summary]

<Callout type="success" title="Was ohne weitere Einrichtung funktioniert">
  - Jedes Paket von reelkit auf dem Server importieren
  - Slider-Komponenten beim SSR rendern (ergibt gültiges statisches HTML)
  - Controller auf dem Server erstellen
  - Overlay-Komponenten bei `isOpen=false`
</Callout>

<Callout type="warning" title="Worauf du achten solltest">
  - Lass `size` für die automatische Messung weg oder gib einen Standardwert vor, wenn die Maße vom Viewport abhängen
  - Rendere `Reel` für Vue in Nuxt innerhalb von `<ClientOnly>`, wenn es eine `size` hat oder du `@reelkit/vue` vor 0.9.1 nutzt
  - Ruf `attach()`/`observe()` nicht auf dem Server auf, wenn du den Core direkt nutzt
</Callout>
