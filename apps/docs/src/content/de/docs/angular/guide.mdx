## URL-State [#url-state]

`createOverlayUrlState` baut einen URL-State-Controller für ein Overlay und gibt ihn vollständig zurück. Du übergibst ihn dann einer `*UrlOverlay`-Komponente als Input `[controller]`. Rufe die Funktion in einem Injection-Kontext auf, also in einem Feld-Initialisierer; sie bindet sich sofort an und gibt sich über `DestroyRef` wieder frei. Die URL bestimmt, ob es offen ist, also öffnet sich ein gebundenes Overlay selbst, und ein Link ist der übliche Weg, es zu öffnen. Das erste Schreiben eines fehlenden Parameters legt einen Eintrag im Verlauf an, jedes weitere Schreiben ersetzt ihn, so dass Blättern den Zurück-Button nie verschüttet. Behalte den Controller, um `value`/`position` zu lesen und ihn im Code zu steuern: `set(position)` öffnet, `set(null)` schließt, und `set` ist dasselbe einfache Schreiben, das das Overlay beim Slide-Wechsel intern nutzt.

App mit Router: Übergib einen Adapter, der den Router nutzt. Sonst veraltet die Location des Routers, und seine nächste Navigation verwirft den Parameter:

<CodeBlock code={urlState2} language="typescript" />

Das Options-Objekt nimmt `param`, `codec` und `locator` (alle drei Pflicht) sowie einen optionalen `adapter`. `codec` und `locator` sind ein zusammengehöriges Paar mit demselben `Id`. Eine einfache Galerie mit `?photo=3` setzt daher `...urlIndexKey(() => images().length)` ein, das beide Hälften auf einmal liefert. `urlIndexKey` prüft den Index gegen die aktuelle Anzahl, die der Getter liefert. Ein veraltetes `?photo=99` wird also abgelehnt und verschwindet von selbst aus der URL, statt eine Slide zu öffnen, die es nie gab. Ein Feed mit Seiten oder eine Galerie mit Schlüsseln nach Identität liefert stattdessen ihr eigenes Paar aus `codec` und `locator`. Die vollständige Tabelle der Optionen steht in der [Angular-API-Referenz](/docs/angular/api#createoverlayurlstate).

## ReelIndicator [#reelindicator]

Optionale Komponente, die Fortschrittsindikatoren wie bei Instagram anzeigt und die aktuelle Position im Slider zeigt. ## Output apiReady — signalbasiertes Muster [#apiready-output-signal-based-pattern]

## Das Wichtigste [#key-points]

<KeyPoints>
<KeyPoint title="Standalone-Komponente">
  Importiere `ReelComponent`, `RkReelItemDirective` und optional `ReelIndicatorComponent` direkt in das Array `imports` deiner Komponente
</KeyPoint>
<KeyPoint title="ng-template + rkReelItem">
  Das Gegenstück in Angular zum Prop `itemBuilder` aus React — es ermöglicht die Virtualisierung
</KeyPoint>
<KeyPoint title="apiReady">
  Ein Output, der einmal mit der API für die imperative Navigation feuert — ohne Abfrage über ViewChild
</KeyPoint>
<KeyPoint title="afterChange">
  Liefert `{ index, indexInRange }` — so verfolgst du den aktuellen Index für die Oberfläche
</KeyPoint>
<KeyPoint title="Standardmäßig OnPush">
  Alle Komponenten nutzen `ChangeDetectionStrategy.OnPush` und Angular-Signals für die beste Performance
</KeyPoint>
</KeyPoints>

## Tipps zur Performance [#performance-tips]

<KeyPoints>
<KeyPoint title="Halte die Slide-Templates schlank">
  Das Template `rkReelItem` läuft für jede sichtbare Slide (meist 3 gleichzeitig). Vermeide darin aufwendige Berechnungen oder tief verschachtelte Strukturen.
</KeyPoint>
<KeyPoint title="Lade Daten nahe am Ende">
  Erkenne mit `(afterChange)`, wann sich der Nutzer dem Ende nähert, und lade den nächsten Schwung, bevor die Slides ausgehen — so entstehen endlos scrollende Feeds.
</KeyPoint>
<KeyPoint title="Nutze Signals für den imperativen Zustand">
  Speichere die Referenz auf `ReelApi` und den aktuellen Index in Angular-Signals. So bekommst du feingranulare Reaktivität, ohne die ganze Komponente neu zu rendern.
</KeyPoint>
<KeyPoint title="Schalte das Mausrad auf scrollbaren Seiten ab">
  Setze `[enableWheel]="false"`, wenn der Slider in einem scrollbaren Layout steckt, damit er das Scrollen der Seite nicht abfängt.
</KeyPoint>
</KeyPoints>
