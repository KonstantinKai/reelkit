## BodyLockService [#bodylockservice]

Блокування прокручування body з підрахунком посилань. Кілька одночасних викликачів (наприклад, відкриті водночас Lightbox і модальне вікно) блокують і розблоковують незалежно — body повертається до норми лише коли останній із них звільнить. Надається на рівні кореня — впроваджуйте будь-де.

<CodeBlock code={bodylockservice} language="typescript" />

| Член | Тип | Опис |
| --- | --- | --- |
| `locked` | `boolean (getter)` | Чи заблоковано body просто зараз |
| `lock()` | `() => void` | Заблокувати прокручування body й компенсувати ширину смуги прокручування |
| `unlock()` | `() => void` | Повернути початкові стилі прокручування body |

## SoundStateService [#soundstateservice]

Стан звуку — вимкнено та недоступно — для оверлея, що відтворює медіа, у вигляді сигналів Angular. Надавайте його на компоненті, який володіє медіа, а не в корені, щоб кожен екземпляр оверлея тримав власний стан. Ним користуються всі оверлеї reelkit для Angular — `@reelkit/angular-reel-player` реекспортує той самий клас, тож наявний імпорт звідти працює далі.

Виняток — lightbox: надавайте сервіс **над** `<rk-lightbox-overlay>`, бо його відеослайд рендериться з вашого шаблону й інакше ніколи не побачить екземпляр усередині оверлея.

<CodeBlock code={soundstateservice} language="typescript" />

| Член | Тип | Опис |
| --- | --- | --- |
| `muted()` | `Signal<boolean>` | Чи вимкнено звук просто зараз. Початково вимкнено |
| `disabled()` | `Signal<boolean>` | Істина, поки звуком не можна керувати, і кнопка звуку ховається. Значення задає оверлей — `RkReelPlayerOverlayComponent` піднімає його, поки слайд без відео або в переході |
| `controller` | `SoundController (getter)` | Базовий `SoundController` із core — передайте його в `syncMutedToVideo`, щоб `<video>` тримався стану звуку |
| `toggle()` | `() => void` | Перемикає вимкнення звуку |
| `setDisabled()` | `(value: boolean) => void` | Задає, чи можна керувати звуком просто зараз |
| `reset()` | `() => void` | Повертає початковий стан: звук вимкнено, керування доступне |

## createOverlayUrlState [#createoverlayurlstate]

<Signature>OverlayUrlStateOptions</Signature>

Будує контролер стану в URL для оверлея, який ви передаєте в `<rk-lightbox-url-overlay>` як його `[controller]` . Викликайте його в контексті впровадження — в ініціалізаторі поля або в конструкторі; він під’єднується одразу й звільняється через `DestroyRef`. Покроковий розбір: [Стан в URL на сторінці Lightbox для Angular](/docs/angular-lightbox#url-state).

| Option | Тип | Типове значення | Опис |
| --- | --- | --- | --- |
| `param` | `string` | `required` | Параметр запиту, що несе активний слайд, наприклад photo. |
| `adapter` | `UrlAdapter` | `History API` | Система навігації, через яку читати й писати. У застосунку з роутером передайте адаптер на базі Router, щоб місцеположення роутера не застаріло. |
| `codec` | `UrlCodec<Id>` | `required` | Формат передавання: текст параметра в стабільну ідентичність. Іде разом із локатором як узгоджена пара — розгорніть ...urlIndexKey(() => images().length) для типової галереї з ?photo=3 або передайте власний, щоб закладка пережила зміну порядку. |
| `locator` | `UrlLocator<Id>` | `required` | Зіставляє ідентичність із позицією і сам відповідає за свою чинність: locate (синхронно), locateAsync (запасний варіант для посторінкової галереї), identify (для запису). |

## createRouterUrlAdapter [#createrouterurladapter]

<Signature>@reelkit/angular/ng-router-url-adapter</Signature>

A `UrlAdapter` на базі Angular Router. Передайте його як `adapter` у `createOverlayUrlState` у застосунку з роутером, щоб Router лишався єдиним джерелом правди про навігацію: запис `history.pushState` повз Router лишає його місцеположення застарілим, і наступна навігація втрачає параметр. Запис торкається лише запиту, тож шлях, фрагмент і повторювані ключі на кшталт `?tag=a&tag=b` лишаються недоторканими. Кожна зміна повідомляє, чи Router додав запис на тій самій сторінці, замінив його чи пройшов історією, тож галерея, відкрита з `routerLink`, закривається одним кроком назад. Викликайте його в контексті впровадження; підписка на роутер звільняється через `DestroyRef`.

Постачається з окремого підшляху, тож застосунок без роутингу ніколи не тягне `@angular/router` у свій бандл. `@angular/router` — необов’язкова peer-залежність.

## Accessibility [#accessibility]

`<rk-reel>` рендериться як `role="region"` з `aria-roledescription="carousel"`. Задайте пропс `ariaLabel` щоб дати області назву для екранного читача. Ввічлива жива область оголошує «Слайд N з M» на кожну зміну слайда. Неактивні слайди отримують атрибут `inert` , тож фокус і навігація допоміжних технологій їх пропускають.

`<rk-reel-indicator>` рендериться як `role="tablist"` з рухомим tabindex на точках; стрілки переміщують фокус, а Enter або Space активує слайд.

Будуєте власне модальне вікно навколо `<rk-reel>`? `captureFocusForReturn`, `createFocusTrap`, та `getFocusableElements` — вони реекспортовані з `@reelkit/angular` для повернення й утримання фокуса.
