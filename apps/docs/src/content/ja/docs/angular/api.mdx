## BodyLockService [#bodylockservice]

参照カウント付きで body のスクロールを止めます。同時に複数の呼び出し元（たとえばギャラリーとモーダルが両方開いている場合）がそれぞれ独立して止めたり解除したりでき、最後の呼び出し元が解除したときにだけ body が元に戻ります。ルートで提供されているので、どこでもインジェクトできます。

<CodeBlock code={bodylockservice} language="typescript" />

| メンバー | 型 | 説明 |
| --- | --- | --- |
| `locked` | `boolean (getter)` | body が現在ロックされているかどうか |
| `lock()` | `() => void` | body のスクロールを止め、スクロールバーの幅を補正します |
| `unlock()` | `() => void` | body の元のスクロールのスタイルに戻します |

## SoundStateService [#soundstateservice]

メディアを再生するオーバーレイのミュート状態と無効状態を、Angular のシグナルとして持ちます。ルートではなくメディアを持つコンポーネントで提供してください。そうすればオーバーレイごとに状態が分かれます。reelkit の Angular オーバーレイはすべてこれを使います。`@reelkit/angular-reel-player` も同じクラスを再エクスポートしているので、そちらからの既存のインポートはそのまま動きます。

例外は lightbox です。ビデオスライドはあなた自身のテンプレートから描画されるため、オーバーレイの内側のインスタンスは見えません。`<rk-lightbox-overlay>` の**上**で提供してください。

<CodeBlock code={soundstateservice} language="typescript" />

| メンバー | 型 | 説明 |
| --- | --- | --- |
| `muted()` | `Signal<boolean>` | 現在ミュートかどうか。最初はミュートです |
| `disabled()` | `Signal<boolean>` | 音を操作できない間は true になり、サウンドボタンが隠れます。値を立てるのはオーバーレイ側で、`RkReelPlayerOverlayComponent` はスライドに動画がないときや切り替え中に立てます |
| `controller` | `SoundController (getter)` | 下地になっている core の `SoundController`。`syncMutedToVideo` に渡すと `<video>` がミュート状態に追従します |
| `toggle()` | `() => void` | ミュートを切り替えます |
| `setDisabled()` | `(value: boolean) => void` | いま音を操作できるかどうかを設定します |
| `reset()` | `() => void` | 最初の状態に戻します。ミュートで、操作は可能です |

## createOverlayUrlState [#createoverlayurlstate]

<Signature>OverlayUrlStateOptions</Signature>

オーバーレイ用の URL 状態コントローラーを作ります。それを `<rk-lightbox-url-overlay>` の `[controller]` 入力に渡します。インジェクションコンテキスト（フィールドの初期化子かコンストラクター）の中で呼んでください。すぐに接続し、`DestroyRef` で解放されます。手順：[Angular Lightbox のページの URL の状態](/docs/angular-lightbox#url-state)。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `param` | `string` | `必須` | アクティブなスライドを持つクエリパラメーター（たとえば photo）。 |
| `adapter` | `UrlAdapter` | `History API` | 読み書きに使うナビゲーションの仕組み。ルーターを使うアプリでは、Router の位置情報が古くならないよう、Router に連動したアダプターを渡してください。 |
| `codec` | `UrlCodec<Id>` | `必須` | 通信形式：パラメーターの文字列から安定した識別子へ。対として locator と一緒に使います。デフォルトの ?photo=3 のギャラリーなら ...urlIndexKey(() => images().length) を展開し、並べ替えてもブックマークが保たれるようにするなら独自のものを用意します。 |
| `locator` | `UrlLocator<Id>` | `必須` | 識別子を位置に対応させ、その妥当性を自分で判断します：locate（同期）、locateAsync（ページングされたギャラリー向けの非同期フォールバック）、identify（書き込み）。 |

## createRouterUrlAdapter [#createrouterurladapter]

<Signature>@reelkit/angular/ng-router-url-adapter</Signature>

Angular の Router に連動した `UrlAdapter` です。ルーターを使うアプリで `createOverlayUrlState` の `adapter` オプションに渡すと、ナビゲーションの信頼できる情報源が Router だけに保たれます。Router の裏で `history.pushState` を書くと、その位置情報が古くなり、次のナビゲーションでパラメーターが消えます。書き込むのはクエリだけなので、パス、フラグメント、`?tag=a&tag=b` のような繰り返しのキーはそのまま残ります。変更のたびに、Router が同じページで push したのか、replace したのか、履歴をたどったのかを報告するので、`routerLink` から開いたギャラリーは 1 回戻るだけで閉じます。インジェクションコンテキストの中で呼んでください。ルーターの購読は `DestroyRef` で解放されます。

独自のサブパスから提供されるので、ルーティングを使わないアプリのバンドルに `@angular/router` が入ることはありません。`@angular/router` は任意の peer dependency です。

## アクセシビリティ [#accessibility]

`<rk-reel>` は `aria-roledescription="carousel"` を持つ `role="region"` として描画されます。`ariaLabel` 入力を指定すると、スクリーンリーダー向けの名前が付きます。控えめなライブリージョンが、スライドが変わるたびに「Slide N of M」と読み上げます。非アクティブなスライドには `inert` 属性が付くので、フォーカスや支援技術での移動では飛ばされます。

`<rk-reel-indicator>` は、ドットにローミング tabindex を持つ `role="tablist"` として描画されます。矢印キーでフォーカスが移動し、Enter か Space でスライドが有効になります。

`<rk-reel>` を囲む独自のモーダルを作るなら、フォーカスを戻したり閉じ込めたりするために `captureFocusForReturn`、`createFocusTrap`、`getFocusableElements` が `@reelkit/angular` から再エクスポートされています。
