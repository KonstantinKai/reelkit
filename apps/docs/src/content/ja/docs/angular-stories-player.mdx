## クイックスタート [#quick-start]

<Callout type="info" title="オーバーレイが描画される場所">
  オーバーレイを `document.body` の末尾へ移す React と Vue のプレーヤーと違い、`rk-stories-overlay` は置いた場所に描画され、`position: fixed` で画面を覆います。`transform`、`perspective`、`filter`、`will-change: transform` を持つ祖先の中には置かないでください。その祖先がオーバーレイの包含ブロックになり、プレーヤーはビューポートではなくその祖先の大きさになり、祖先の `overflow` で切り取られます。独自のスタッキングコンテキストを作る祖先も、`--rk-stories-overlay-z` でプレーヤーをどこまで持ち上げられるかを制限します。その代わり、どの祖先に設定した `--rk-stories-*` トークンもプレーヤーに届きます。

## URL の状態 [#url-state]

<DemoLink href="https://angular-demo.reelkit.dev/stories-player-url?utm_source=docs">ライブデモを見る →</DemoLink>

`RkStoriesUrlOverlayComponent` は、開いているかどうかをアドレスバーに置く別コンポーネントです。2 つの軸が 1 つのパラメーター `?story=<group>.<story>` に乗るので、再生中のストーリーには共有・ブックマークでき、戻るボタンで閉じられるリンクが付きます。`createOverlayUrlState` と `urlIndexTwoAxisKey` でコントローラーを作り、`controller` として渡してください。

<Callout type="info" title="組み込みのキー">
  ストーリーは 2 軸なので、2 軸のキーをコントローラーに展開します。`urlIndexTwoAxisKey`（ユーザーとストーリーを位置で指定）か `urlStableIdTwoAxisKey`（ユーザーを安定した `id` で指定）のどちらかで、いずれも `@reelkit/angular-stories-player` から再エクスポートされています。[URL 状態ガイド](/docs/core/guide#url-state)と [Core API](/docs/core/api#url-state) も参照してください。
</Callout>

<CodeBlock code={urlState} language="typescript" />

- 開くと履歴が **1 件** 積まれます。ストーリー間の移動*も*ユーザーの切り替えも、その 1 件を **置き換える** だけなので、何回操作しても履歴は増えず、戻る 1 回で必ずプレイヤーが閉じます。戻るは閉じる操作であって、ストーリーを 1 つ戻す操作ではありません。
- **内側の移動も URL に乗ります。** 同じユーザーのストーリーを進めると `?story=2.`*n* が更新されるので、ディープリンクはそのストーリーちょうどに着きます。
- 戻るで閉じるのは、アプリ内からプレイヤーを開いたときだけです。そのリンクが履歴を 1 件積んでいるからです。新しいタブで直接開いた共有リンクには背後に履歴がないので、ブラウザーの戻るはサイトの外へ出ます。✕ ボタンや Escape はその場でパラメーターを消し、ページにとどまります。
- ユーザーもストーリーも指していないパラメーター（古いブックマーク、手で書き換えた値、グループの終わりを超えた番号）は、隣を開くのではなく URL から取り除かれます。
- ルーターを使うアプリは、ルーター側のアダプターを渡してください。ナビゲーションの正となる場所をルーターに一本化するためです。`@reelkit/angular/ng-router-url-adapter` の `createRouterUrlAdapter` が Angular ルーター用の既製アダプターです。ルーターの背後で履歴を書くと location が古いままになり、次のナビゲーションでパラメーターが落ちます。

**安定したリンク。** ユーザーは既定では位置で指定されるため、ブックマークした `?story=2.0` はフィードの並びが変わると別の人を開きます。代わりに安定した id で指定してください。`outerCodec` が id を URL に書き、`outerLocator` がその位置を見つけます。`innerCodec` を `innerLocate`・`innerIdentify` とともに渡せば、グループ内のストーリーにも同じことができます。渡さなければ、ストーリー側はグループ内の普通のローカルなインデックスのままです。

<CodeBlock code={urlState2} language="typescript" />

**無限フィード。** ページングは codec とは独立した `outerLocator` の仕事です。`locate` は同期なので、すでに読み込まれたグループにしか答えられません。20 件しか読み込んでいないフィードで 400 番目のグループを指す共有リンクは空振りします。`locateAsync` はその控えで、`locate` が外したときだけ呼ばれます。ストーリーはその後、落ち着いた先のグループに合わせて範囲が取り直されます。

<Callout type="info" title="同じ locateAsync、外側の軸">
  これは 1 軸のキーが受け取るのと同じ `locateAsync` ページャーです。2 軸のキーでは渡した `outerLocator` に乗るので、ページングはユーザーの軸で起こり、ストーリーは解決されたグループ内のローカルなインデックスのままです。
</Callout>

<CodeBlock code={urlState3} language="typescript" />

- `locateAsync` が待機している間、プレイヤーは閉じたままでパラメーターもそのままなので、ディープリンクは取得をまたいで生き残ります。`null` や拒否ならパラメーターは取り除かれます。
- URL が変わったあと、閉じたあと、アンマウントしたあとに届いた答えは破棄されます。遅い取得が、もう誰も求めていないストーリーを開くことはありません。
- `createOverlayUrlState` の全オプションは [Angular API リファレンス](/docs/angular/api#createoverlayurlstate)にあり、手順の解説は [Angular ガイド](/docs/angular/guide#url-state)にあります。

## 見たものを覚えておく [#remembering-what-was-seen]

リングはグループを最後まで見るまでグラデーションを表示し、グループは視聴者がまだ見ていない最初のストーリーから開き直します。どちらも 1 つの `createStoriesViewedStateController` から来ます。フィードのある場所で一度だけ作り、`viewed` としてリングリストとプレイヤーに渡してください。両者はストアを読み、変化に追従し、表示したものを自分で記録します。保存されるエントリーは著者とストーリーを id で指すので、フィードの並べ替えにも耐え、同じコントローラーが React と Vue でも動きます。

<CodeBlock code={rememberingWhatWasSeen} language="typescript" />

- **開いたときのストーリーも数えます。** プレイヤーが開くときに画面に出ているストーリーは視聴済みとして報告されるので、ストーリーが 1 つのグループを開いて閉じれば視聴済みになります。
- **スワイプで先へ進んでも再開します。** `resumeStoryIndex` は、このセッションで初めて到達したすべてのグループについて問い合わせられます。プレイヤーが開くグループも含みますが、`initialStoryIndex` がストーリーを明示している場合は除きます。すでにスワイプで通ったグループは、離れたところから開き直します。明示した `resumeStoryIndex` 入力はコントローラーの答えより優先されます。
- **リンクはそれでも優先されます。** `rk-stories-url-overlay` では、保存内容にかかわらずパラメーターがプレイヤーの開く場所を決めます。それ以外の場所では再開のコールバックが決めます。
- **数は位置であって、集計ではありません。** エントリーは到達したいちばん先のストーリーを指すので、視聴済みのグループにストーリーを追加するとリングは再び光り、途中のストーリーを削除すると数は短くなります。
- **ストレージは差し替えられます。** タブを閉じたら忘れるには `storage: createSessionStorageAdapter()` を、あるいは独自の `StorageAdapter` を渡してください。開いている 2 つのタブは、ブラウザーの storage イベントで同期されます。
- **開いたときにだけ作られるプレイヤーでは、読み込みが遅すぎます。** `rk-stories-overlay` は、閉じている間でも存在した時点でストアを読み、`rk-stories-ring-list` も同様です。`@if (open)` で包んだオーバーレイにはその機会がないので、ホストのコンストラクターで `attachViewedState(() => this.viewed)` を呼んでください。ホストが存在する間、接続が続きます。オプションと、これを構成する低レベルの部品は [Stories Core](/docs/stories-core#viewed-controller) のページにあります。

## デスクトップのカルーセル [#desktop-carousel]

`desktopLayout="carousel"` を指定すると、Instagram の Web ビューアーのようなレイアウトになります。表示中のストーリーは通常の大きさのまま中央にとどまり、両側に最大 2 つずつ隣のグループが小さく暗めのカードとして並びます。カードをクリックするとそのグループが開き、グループが変わる間カードは横へスライドします。リングリストが受け取るのと同じ `viewed` コントローラーを渡せば、視聴済みのグループのカードは控えめなリングになります。

<CodeBlock code={desktopCarousel} language="typescript" />

- **スマートフォンでは普通のプレイヤーのままです。** 幅 768px まではカードは描画されず、スワイプはデフォルトの `'single'` レイアウトと同じく `groupTransition` を使います。その幅をまたいでリサイズすると、その場で切り替わります。カードが表示されている間、グループは `groupTransition` の指定にかかわらず回転せずスライドします。
- **各カードは、そのグループが開く場所をプレビューします**：このセッションで離れたときのストーリー、なければ `resumeStoryIndex` が返すものです。動画のポスターか画像を表示します。どちらもないストーリー（グラデーション上のテキストのストーリーなど）は、`rkStoriesSlide` テンプレートでプレイヤーの大きさに描いて縮小します。ポスターのない動画はカードの背景を表示します。このプレビューは `isActive: false` を受け取り、ライフサイクルのコールバックは何もしないので、画面上のストーリーのタイマーを動かすことはできません。スライドが作られたときに行う処理（再生や分析など）は `isActive` の後ろに置いてください。
- **タイマーはスライドを待ちます。** カードの移動が終わるまで、ストーリーはタイマーを開始せず、`(storyViewed)` も発行されません。
- **グループを変えるすべての方法でスライドします**：カードのクリック、`StoriesApi.goToGroup`、`nextGroup` と `prevGroup`、そしてグループの端を越える矢印キーです。タッチのスワイプはプレイヤー自体を動かすので、その上にスライドは加わりません。
- **カードの見た目を変える**には `rkStoriesGroupPreview` スロットを使います。[カルーセルカードのカスタマイズ](#custom-carousel-cards)を参照してください。カードの配置・拡大縮小・スライドは引き続きプレイヤーが行います。

## グループごとのプログレスバーとヘッダー [#chrome-placement]

デフォルトでは、プログレスバーとヘッダーが 1 つずつプレーヤーの上にあり、グループが切り替わった後で新しいグループの表示に変わります。`chromePlacement="group"` を指定すると、各グループが自分のスライドの中に専用のプログレスバーとヘッダーを持ち、Instagram と同じようにグループと一緒に回転します。

<CodeBlock code={chromePlacement} language="typescript" />

- **隣のグループは、どこまで見たかを表示します。** プレーヤーがそのグループへ回転している間、プログレスバーとヘッダーは、そのグループが開くストーリーを、まだ何も再生していない状態で表示します。
- **離れていくグループはそのままの状態を保ちます。** 回転が終わるまでプログレスバーはそれまでの進み具合を保つので、最後まで見たグループは回転の途中で空にならず、満たされたままです。
- **テンプレートは画面上のグループそれぞれに対して描かれます。** `rkStoriesProgressBar` と `rkStoriesHeader` のコンテキストには `groupIndex` と `isActive` が含まれます。隣のグループでは `isActive` が `false` になり、進捗のシグナルは変化しません。
- **`rkStoriesHeader` テンプレートはスワイプ領域の中にあります。** ヘッダーをタップするとストーリーが切り替わります。ただし `button`、リンク、`role="button"` を持つ要素の上なら切り替わらないので、ヘッダー内の操作要素はすべてそのいずれかにしてください。
- **デスクトップのカルーセルでは、スライド中の見た目は変わりません。** カードがスライドしている間はプレーヤーが隠れるため、この設定はグループが開いてから反映されます。

## テンプレートスロット [#template-slots]

8 つの `ng-template` ディレクティブがプレイヤーのどの部分でも差し替えます。それぞれ型付きのコンテキストを受け取り、すべての値に React と Vue のスロットと同じ名前が付いています。たとえばヘッダースロットでは `let-author="author"` で著者を受け取れます。主な値は暗黙値でもあるので、`let-author` だけでも同じです。渡さなかったスロットは既定の表示のままです。

| ディレクティブ | クラス | コンテキスト | 説明 |
| --- | --- | --- | --- |
| `rkStoriesError` | `RkStoriesErrorDirective` | `{ $implicit: story, story, storyIndex, groupIndex }` | 組み込みの "Content unavailable" パネルを差し替えます。表示中のストーリーの上に描かれます |
| `rkStoriesFooter` | `RkStoriesFooterDirective` | `{ $implicit: story, story, author, storyIndex }` | 表示中のストーリーの下にフッターを追加します。プレイヤー自身はフッターを描きません |
| `rkStoriesGroupPreview` | `RkStoriesGroupPreviewDirective` | `{ $implicit: group, group, groupIndex, story, offset, viewedCount, onOpen }` | デスクトップのカルーセルカードの中身を差し替えます。配置・拡大縮小・スライドはプレイヤーが引き続き行います |
| `rkStoriesHeader` | `RkStoriesHeaderDirective` | `{ $implicit: author, author, story, storyIndex, isPaused, isMuted, isVideo, groupIndex, isActive, onToggleSound, onTogglePause, onClose }` | 既定のヘッダー（著者、一時停止、サウンド、閉じる）を差し替えます。`chromePlacement="group"` ではスワイプ領域の中に入ります。[グループごとのプログレスバーとヘッダー](/docs/angular-stories-player#chrome-placement)を参照してください。 |
| `rkStoriesLoading` | `RkStoriesLoadingDirective` | `{ $implicit: story, story, storyIndex, groupIndex }` | 表示中のストーリーの読み込み中に出る、既定のヘッダーのスピナーを差し替えます |
| `rkStoriesNavigation` | `RkStoriesNavigationDirective` | `{ onPrevStory, onNextStory, onPrevGroup, onNextGroup, $implicit: { the same four } }` | デスクトップの矢印を両方とも差し替えます |
| `rkStoriesProgressBar` | `RkStoriesProgressBarDirective` | `{ $implicit: group, group, totalStories, activeIndex, progress, groupIndex, isActive }` | canvas のプログレスバーを差し替えます。`activeIndex` と `progress` はコアのシグナルなので、`toAngularSignal` で橋渡ししてください。 |
| `rkStoriesSlide` | `RkStoriesSlideDirective` | `{ $implicit: story, story, index, groupIndex, isActive, size, activeGroupIndex, activeStoryIndex, onDurationReady, onReady, onWaiting, onError, onEnded }` | 既定の画像スライドと動画スライドを差し替えます |

<CodeBlock code={templateSlots} language="typescript" />

`STORIES_TEMPLATE_SLOT_DIRECTIVES` は 8 つのクラスをまとめた配列として公開されています。複数をインポートするコンポーネント向けです。

どのスロットもプレイヤー自身のインジェクター経由で描画されるため、スロット内に置いたコンポーネントはプレイヤーのプロバイダーを解決できます。スライドテンプレート内の `rk-video-story-slide` は、ヘッダーのボタンが書き込むのと同じサウンド状態を受け取ります。

### スライドのカスタマイズ [#custom-slides]

<CodeBlock code={slideSlot} language="typescript" />

カスタムスライドは、`rkStoriesSlide` コンテキストのコールバックを通して、コンテンツの状態をプレイヤーに伝えます。プレイヤーが反応するのは画面上のストーリーからの呼び出しだけで、他のスライドからの呼び出しは無視されます。

| コールバック | いつ |
| --- | --- |
| `onReady` | コンテンツの準備ができた（画像が読み込まれた、動画が再生中）。プログレスタイマーが始まるか、カルーセルのスライドが終わるのを待ちます。 |
| `onWaiting` | コンテンツが止まった（再生途中の動画のバッファリング）。スピナーが表示され、タイマーは一時停止します。 |
| `onError` | コンテンツの読み込みに失敗した。エラーパネルが表示され、タイマーは一時停止します。 |
| `onDurationReady` | 実際のメディアの長さをミリ秒で報告します（たとえば動画のメタデータから）。タイマーがそれに合わせます。ストーリーに設定した `duration` のほうが優先されます。 |
| `onEnded` | メディアが自然に終わった（たとえば動画が最後まで再生された）。プレイヤーはタイマーを待たずに次のストーリーへ進みます。 |

`rk-image-story-slide` は `(loaded)` と `(failed)` を、`rk-video-story-slide` は `(playbackStarted)`、`(buffering)`、`(failed)`、`(durationReady)`、`(finished)` を発行するので、これらを包むスライドテンプレートは、それぞれを対応するコールバックに渡すだけで済みます。

<Callout type="info" title="プリローダーのキャッシュ">
  組み込みの `RkImageStorySlideComponent` と `RkVideoStorySlideComponent` は次のストーリーをバックグラウンドで先読みします。先読み済みのストーリーに進むと、読み込み中の表示なしで即座にコンテンツが現れます。一度失敗した URL も記憶されるため、壊れたストーリーを開き直したときは再試行せずすぐにエラーを表示します。
</Callout>

## アクセシビリティ [#accessibility]

オーバーレイのルートはモーダルダイアログです（`role="dialog"`、`aria-modal="true"`）。スクリーンリーダーの読み上げを変えるには `ariaLabel` を設定してください。既定は "Stories player" です。

オーバーレイは開いたときにフォーカスを取り込み、閉じたときに元の要素へ戻します。Tab と Shift+Tab は内部のフォーカス可能な要素を巡回し、両端で折り返します。外れたフォーカス（外側のクリック、プログラムによるフォーカス）は引き戻されます。プレイヤーが開いている間、body のスクロールはロックされます。`@reelkit/core` の `captureFocusForReturn` と `createFocusTrap`（`@reelkit/angular` が再エクスポート）で実装しています。

デスクトップのカルーセルでは、既定のカードはそれぞれ "Open stories by" と著者名をラベルに持つボタンです。カードはタブ順でプレイヤーの操作ボタンより後に並び、スライド中はタブ順から外れます。自分のグループを開いたカードは、フォーカスをページに落とさずダイアログへ返します。

## サーバーサイドレンダリング [#server-side-rendering]

プレイヤーは開かれるまで何も描画せず、構築時にブラウザ API を読まないため、Angular SSR でも安全です。既読状態はレンダリング中ではなくマウント後に読むので、サーバーでのレンダリングと最初のクライアントレンダリングが食い違いません。

## キーボードショートカット [#keyboard-shortcuts]

| キー | 動作 |
| --- | --- |
| `ArrowLeft` | 前のストーリー。グループの最初のストーリーでは前のグループを、離れたところから開きます。最初のグループでは何もしません。 |
| `ArrowRight` | 次のストーリー。グループの最後のストーリーでは次のグループへ移り、最後のグループではプレイヤーが閉じます。 |
| `Escape` | プレイヤーを閉じる |
