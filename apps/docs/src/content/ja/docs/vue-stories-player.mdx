## URL の状態 [#url-state]

<DemoLink href="https://vue-demo.reelkit.dev/stories-player-url?utm_source=docs">ライブデモを見る →</DemoLink>

`StoriesUrlOverlay` は、開いているかどうかをアドレスバーに置く別コンポーネントです。2 つの軸が 1 つのパラメーター `?story=<group>.<story>` に乗るので、再生中のストーリーには共有・ブックマークでき、戻るボタンで閉じられるリンクが付きます。`useOverlayUrlState` と `urlIndexTwoAxisKey` でコントローラーを作り、`controller` として渡してください。

<Callout type="info" title="組み込みのキー">
  ストーリーは 2 軸なので、2 軸のキーをコントローラーに展開します。`urlIndexTwoAxisKey`（ユーザーとストーリーを位置で指定）か `urlStableIdTwoAxisKey`（ユーザーを安定した `id` で指定）のどちらかで、いずれも `@reelkit/vue-stories-player` から再エクスポートされています。[URL 状態ガイド](/docs/core/guide#url-state)と [Core API](/docs/core/api#url-state) も参照してください。
</Callout>

<CodeBlock code={urlState} language="vue" />

- 開くと履歴が **1 件** 積まれます。ストーリー間の移動*も*ユーザーの切り替えも、その 1 件を **置き換える** だけなので、何回操作しても履歴は増えず、戻る 1 回で必ずプレイヤーが閉じます。戻るは閉じる操作であって、ストーリーを 1 つ戻す操作ではありません。
- **内側の移動も URL に乗ります。** 同じユーザーのストーリーを進めると `?story=2.`*n* が更新されるので、ディープリンクはそのストーリーちょうどに着きます。
- 戻るで閉じるのは、アプリ内からプレイヤーを開いたときだけです。そのリンクが履歴を 1 件積んでいるからです。新しいタブで直接開いた共有リンクには背後に履歴がないので、ブラウザーの戻るはサイトの外へ出ます。✕ ボタンや Escape はその場でパラメーターを消し、ページにとどまります。
- ユーザーもストーリーも指していないパラメーター（古いブックマーク、手で書き換えた値、グループの終わりを超えた番号）は、隣を開くのではなく URL から取り除かれます。
- ルーターを使うアプリは、ルーター側のアダプターを渡してください。ナビゲーションの正となる場所をルーターに一本化するためです。`@reelkit/vue/vue-router-url-adapter` の `useVueRouterUrlAdapter` が Vue Router 用の既製アダプターです。ルーターの背後で履歴を書くと location が古いままになり、次のナビゲーションでパラメーターが落ちます。

**安定したリンク。** ユーザーは既定では位置で指定されるため、ブックマークした `?story=2.0` はフィードの並びが変わると別の人を開きます。代わりに安定した id で指定してください。`outerCodec` が id を URL に書き、`outerLocator` がその位置を見つけます。`innerCodec` を `innerLocate`・`innerIdentify` とともに渡せば、グループ内のストーリーにも同じことができます。渡さなければ、ストーリー側は解決されたグループ内の普通のインデックスのままです。ストーリーの id には、2 つの部分の区切りである `.` を含めてはいけません。

<CodeBlock code={urlState2} language="typescript" />

**無限フィード。** ページングは codec とは独立した `outerLocator` の仕事です。`locate` は同期なので、すでに読み込まれたグループにしか答えられません。20 件しか読み込んでいないフィードで 400 番目のグループを指す共有リンクは空振りします。`locateAsync` はその控えで、`locate` が外したときだけ呼ばれます。ストーリーはその後、落ち着いた先のグループに合わせて範囲が取り直されます。

<Callout type="info" title="同じ locateAsync、外側の軸">
  これは 1 軸のキーが受け取るのと同じ `locateAsync` ページャーです。2 軸のキーでは渡した `outerLocator` に乗るので、ページングはユーザーの軸で起こり、ストーリーは解決されたグループ内のローカルなインデックスのままです。
</Callout>

<CodeBlock code={urlState3} language="typescript" />

- `locateAsync` が待機している間、プレイヤーは閉じたままでパラメーターもそのままなので、ディープリンクは取得をまたいで生き残ります。`null` や拒否ならパラメーターは取り除かれます。
- URL が変わったあと、閉じたあと、アンマウントしたあとに届いた答えは破棄されます。遅い取得が、もう誰も求めていないストーリーを開くことはありません。
- `useOverlayUrlState` の全オプションは [Vue API リファレンス](/docs/vue/api#useoverlayurlstate)にあります。

## どこまで見たかを覚える [#remembering-what-was-seen]

リングは、そのユーザーを最後まで見るまでグラデーションのままで、グループはまだ見ていない最初のストーリーから開き直します。どちらも 1 つの `createStoriesViewedStateController` から来ます。フィードのある場所で一度だけ作り、リング一覧とプレイヤーに `viewed` として渡せば、ストレージの読み取りも追従も、表示したストーリーの記録も自分でやります。保存される項目は作者とストーリーを id で記録するので、フィードの並べ替えにも耐え、同じコントローラーが React と Angular でも使えます。

<CodeBlock code={rememberingWhatWasSeen} language="vue" />

- **最初に開いたストーリーも数に入ります。** すでに画面に出ているストーリーは、プレイヤーがマウントした時点で既読として報告されます。ストーリーが 1 つだけのグループを開いて閉じれば、それで見終わった扱いです。
- **先へ進んだ分も再開します。** `resumeStoryIndex` は、このセッションで初めて到達したすべてのグループに対して呼ばれます。プレイヤーが最初に開くグループも含みます（`initialStoryIndex` でストーリーを明示した場合を除く）。すでに見送ったグループは、離れた場所から開き直します。
- **リンクのほうが強い。** `StoriesUrlOverlay` では、何が保存されていてもパラメーターが開く位置を決めます。それ以外の場面では再開コールバックが決めます。
- **カウントは合計ではなく位置です。** 項目は到達した最も先のストーリーを指すので、見終わったグループにストーリーを足せばリングはまた点灯し、途中の 1 つを削ればカウントは縮みます。
- **ストレージは差し替えられます。** タブを閉じたら忘れるなら `storage: createSessionStorageAdapter()` を、独自の保存先なら自作の `StorageAdapter` を渡してください。開いている 2 つのタブは、ブラウザーの storage イベントで足並みをそろえます。
- **開くときだけマウントするプレイヤーは読むのが遅すぎます。** オーバーレイは、まだ閉じた状態のマウント後にストレージを読みます。`v-if="open"` ではその瞬間がないので、`onMounted` で自分で `viewed.attach()` を呼び、返ってきた後始末を `onUnmounted` で呼んでください。オプションと、これを組み立てている低レベルの部品は [Stories Core](/docs/stories-core#viewed-controller) のページにあります。

## デスクトップのカルーセル [#desktop-carousel]

`desktop-layout="carousel"` を指定すると、Instagram のウェブ版のような配置になります。表示中のストーリーはいつもの大きさで中央に残り、その両側に最大 2 つずつ、隣のユーザーが小さく暗いカードとして並びます。カードをクリックするとそのユーザーが開き、グループが変わる間はカードがスライドします。リング一覧に渡したのと同じ `viewed` コントローラーを渡せば、見終わったグループのカードのリングは暗くなります。カードは自分でコントローラーを追うので、ストーリーが既読になったときに描き直されるのはカードだけで、プレイヤーは再描画されません。

<CodeBlock code={desktopCarousel} language="vue" />

- **スマートフォンでは普通のプレイヤーのままです。** 幅 768px 以下ではカードは描画されず、スワイプは既定の `'single'` レイアウトと同じく `group-transition` を使います。その幅をまたいでリサイズすると、その場で切り替わります。
- **各カードはグループが開く場所を映します。** このセッションで離れたストーリー、なければ `resumeStoryIndex` が返すストーリーです。動画のポスターか画像を表示します。そのどちらも持たないストーリー（グラデーション上のテキストストーリーなど）は、あなたの `#slide` スロットがプレイヤーの大きさで描いたものを縮小して使います。ポスターのない動画はカードの背景を見せます。このプレビューには `isActive: false` が渡り、ただの絵として扱われます。フォーカスもクリックもできません。再生や計測など、スライドがマウント時に行う処理は `isActive` の内側に置いてください。
- **タイマーはスライドを待ちます。** カードが動き終わるまで、ストーリーは進まず、`story-viewed` もそのストーリーについては発行されません。
- **グループを変えるどの操作でもスライドします。** カードのクリック、`StoriesApi.goToGroup`、`nextGroup` と `prevGroup`、グループの端を越える矢印キーです。タッチのスワイプはプレイヤー自体を動かすので、その上にスライドは重なりません。

## グループごとのプログレスバーとヘッダー [#chrome-placement]

デフォルトでは、プログレスバーとヘッダーが 1 つずつプレーヤーの上にあり、グループが切り替わった後で新しいグループの表示に変わります。`chrome-placement="group"` を指定すると、各グループが自分のスライドの中に専用のプログレスバーとヘッダーを持ち、Instagram と同じようにグループと一緒に回転します。

<CodeBlock code={chromePlacement} language="vue" />

- **隣のグループは、どこまで見たかを表示します。** プレーヤーがそのグループへ回転している間、プログレスバーとヘッダーは、そのグループが開くストーリーを、まだ何も再生していない状態で表示します。
- **離れていくグループはそのままの状態を保ちます。** 回転が終わるまでプログレスバーはそれまでの進み具合を保つので、最後まで見たグループは回転の途中で空にならず、満たされたままです。
- **スロットは画面上のグループそれぞれに対して描かれます。** `#progressBar` と `#header` のスコープには `groupIndex` と `isActive` が含まれます。隣のグループでは `isActive` が `false` になり、進捗のシグナルは変化しません。
- **`#header` スロットはスワイプ領域の中にあります。** ヘッダーをタップするとストーリーが切り替わります。ただし `button`、リンク、`role="button"` を持つ要素の上なら切り替わらないので、ヘッダー内の操作要素はすべてそのいずれかにしてください。
- **デスクトップのカルーセルでは、スライド中の見た目は変わりません。** カードがスライドしている間はプレーヤーが隠れるため、この設定はグループが開いてから反映されます。

### StoriesUrlOverlay のプロパティ [#storiesurloverlay-props]

<Signature>StoriesUrlOverlayProps</Signature>

上記のプロパティをすべて受け取りますが、開閉位置の 3 つ（`is-open`、`initial-group-index`、`initial-story-index`）は例外で、これらはコントローラーから与えられます。

| Prop | 型 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `controller` | `UrlStateController<TwoAxisPosition>` | `required` | `urlIndexTwoAxisKey` を展開した `useOverlayUrlState` のコントローラー。その `position`（\{ outer, inner \} のオブジェクト）が、プレイヤーを開くかどうかとどこから開くかを決めます。オーバーレイは移動のたびと閉じるときに書き戻します。 |

| イベント | ペイロード | 説明 |

## スコープ付きスロット [#scoped-slots]

8 つのスコープ付きスロットで、プレイヤーのどの部分も差し替えられます。それぞれ型の付いたスコープオブジェクトを受け取ります。渡さなかったスロットは既定のままで、何も描かなかったスロットも同じ扱いです。したがって false になった `v-if` は、穴を残すのではなく既定に戻ります。

| スロット | スコープ | 説明 |
| --- | --- | --- |
| #error | `{ story, storyIndex, groupIndex }` | 表示中のストーリーの上に描かれる組み込みの「Content unavailable」パネルを差し替えます |
| #footer | `{ author, story, storyIndex }` | 表示中のグループのストーリーの下にフッターを足します |
| #groupPreview | `{ group, groupIndex, story, offset, viewedCount, onOpen }` | デスクトップのカルーセルのカードの中身を描きます。配置・拡縮・スライドは引き続きプレイヤーが行います |
| #header | `{ author, story, storyIndex, isPaused, isMuted, isVideo, groupIndex, isActive, onToggleSound, onTogglePause, onClose }` | 既定のヘッダー（作者、一時停止、サウンド、閉じる）を差し替えます。`chrome-placement="group"` ではスワイプ領域の中に入ります。[グループごとのプログレスバーとヘッダー](/docs/vue-stories-player#chrome-placement)を参照してください。 |
| #loading | `{ story, storyIndex, groupIndex }` | 表示中のストーリーの読み込み中に出る、既定のヘッダーのスピナーを差し替えます |

### スライドをカスタマイズする [#custom-slides]

`#slide` の中で `ImageStorySlide` と `VideoStorySlide` を組み合わせれば、自動再生・ポスターの取得・サウンドの同期を保ったまま、自分のレイアウトを描けます。スコープのライフサイクルコールバックを呼んでください。呼ばないとタイマーは永遠に始まりません。

| `onError` | コンテンツの読み込みに失敗した。エラー表示にし、その URL は壊れたものとして覚えるので、開き直しても再試行しません。 |
| `onDurationReady` | メディアの実際の長さをミリ秒で伝えます。タイマーが動画と同じだけ動くようになります。 |
| `onEnded` | メディアが終わった。次のストーリーへ進みます。 |

## 再エクスポート [#re-exports]

利用側に必要なものはすべてこのパッケージから来るので、`@reelkit/core` を直接インポートする必要はありません。

| 取得元 | 再エクスポートされるもの |
| --- | --- |
| `@reelkit/vue` | `Observe`、`SoundProvider`、`useSoundState`、`useOverlayUrlState`、`createViewedStateController`、`twoAxisViewedTracking`、`createLocalStorageAdapter`、`createSessionStorageAdapter`、`createMemoryStorageAdapter`、`urlIndexTwoAxisKey`、`urlStableIdTwoAxisKey`、`base64UrlCodec`、および型 `UrlAdapter`、`UrlCodec`、`UrlLocator`、`UrlKey`、`UrlStateController`、`TwoAxisPosition`、`TwoAxisIdentity`、`UrlIndexTwoAxisKeyOptions`、`ViewedStateController`、`ViewedStateOptions`、`StorageAdapter` |
| `@reelkit/stories-core` | `createStoriesViewedStateController`、`StoriesViewedStateController`、`StoriesViewedStateControllerConfig`、およびコンテンツの型 `StoryItem`、`AuthorInfo`、`StoriesGroup`、`MediaType` |

`Observe` は、プレイヤーが内部で使っている描画の境界です。core のシグナルが変わったときに自分のスロットだけを描き直すので、ストーリーが変わってもヘッダーとプログレスバーだけが更新され、2 つのスライダーは描き直されません。`toVueRef` でコンポーネント全体がシグナルを追うのでは粗すぎるとき、自作のスロットの中で使ってください。詳しくは [Vue API リファレンス](/docs/vue/api#observe)へ。

各コンポーネントのプロパティ型も公開されています。`StoriesOverlayProps`、`StoriesUrlOverlayProps`、`StoriesRingProps`、`StoriesRingListProps`、`StoryHeaderProps`、`CanvasProgressBarProps`、`ImageStorySlideProps`、`VideoStorySlideProps`。

## アクセシビリティ [#accessibility]

オーバーレイのルートはモーダルダイアログです（`role="dialog"`、`aria-modal="true"`）。スクリーンリーダーの読み上げを変えるには `aria-label` を設定してください。既定は「Stories player」です。

オーバーレイは開くときにフォーカスを預かり、閉じるときに元の要素へ返します。Tab と Shift+Tab は内側のフォーカス可能な要素を巡り、外へ逃げたフォーカスは引き戻されます。`@reelkit/core` の `captureFocusForReturn` と `createFocusTrap`（`@reelkit/vue` が再エクスポート）で実装しています。

デスクトップのカルーセルでは、既定のカードはそれぞれ「Open stories by」と作者名のラベルを持つボタンです。カードはタブ順でプレイヤーの操作のあとに並び、スライド中はタブ順から外れます。自分のグループを開いたカードは、フォーカスをページに落とさずダイアログへ返します。

## サーバーサイドレンダリング [#server-side-rendering]

閉じている間、オーバーレイは何も描画しません。`StoriesRingList` はサーバー側ではすべてのリングを未読として描画します。既読のストレージはマウント後にしか読まないので、サーバーのマークアップと最初のクライアント描画が一致します。全体像は [SSR ガイド](/docs/ssr)にあります。

## キーボードショートカット [#keyboard-shortcuts]

| キー | 動作 |
| --- | --- |
| `ArrowLeft` | 前のストーリー。グループの最初のストーリーでは前のグループを、離れたところから開きます。最初のグループでは何もしません。 |
| `ArrowRight` | 次のストーリー。グループの最後のストーリーを過ぎると次のグループを開きます。最後のグループではプレイヤーを閉じます。 |
| `Escape` | プレイヤーを閉じる |
