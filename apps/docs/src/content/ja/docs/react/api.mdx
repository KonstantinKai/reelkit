## オブザーバーコンポーネント [#observer-components]

### Observe [#observe]

親を再レンダリングさせずに、コアのシグナルを React の描画につなぎます。購読しているシグナルが変わったときに再実行されるのは、children の関数だけです。

<CodeBlock code={observe} language="tsx" />

| Prop | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `signals` | `Subscribable[]` | `必須` | 購読するシグナル。どれかが通知すると children の関数が再実行されます。再実行されるのはその関数だけで、親は再レンダリングされません。後のレンダーで別のシグナルを渡すと、置き換えられたものの代わりにそちらを追従します。 |
| `children` | `() => ReactElement \| null` | `必須` | 変更のたびに再実行される描画関数。シグナルの値はこの中で読んでください。外で読んだ値は一度だけ取り込まれ、古くなります。 |

### AnimatedObserve [#animatedobserve]

アニメーションする値のシグナルを購読し、`requestAnimationFrame` でなめらかに補間します。

<CodeBlock code={animatedobserve} language="tsx" />

| Prop | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `signal` | `Signal<AnimatedValue>` | `必須` | \{ value, duration, done? \} を出すシグナル。duration が 0 より大きければ現在の値から新しい値へ補間し、0 ならすぐその値になります。 |
| `children` | `(value: number) => ReactElement` | `必須` | 現在のフレームの補間された値を受け取る描画関数。DOM がアニメーションに遅れないよう、同期的に反映されます。 |

### useOverlayUrlState [#useoverlayurlstate]

<Caption>`OverlayUrlStateOptions`</Caption>

オーバーレイ用の URL 状態コントローラーを作ります。それを `*UrlOverlay` の `controller` プロップに渡します。

手順と例は [React ガイドの URL の状態](/docs/react/guide#url-state) を参照してください。

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `param` | `string` | 必須 | アクティブなスライドを持つクエリパラメーター（たとえば "photo"）。最初の描画で読まれ、コンポーネントが生きているあいだは固定です。変えるには再マウント（key を付ける）してください。 |
| `adapter` | `UrlAdapter` | History API | 読み書きに使うナビゲーションの仕組み。ルーターを使うアプリでは、ルーター自身の位置情報が古くならないよう、ルーターに連動したアダプターを渡してください。最初の描画で読まれ、コンポーネントが生きているあいだは固定です。変えるには再マウントしてください。 |
| `codec` | `{ decode(raw) => Id \| null; encode(id) => string }` | 必須 | 通信形式：パラメーターの文字列 ↔ 安定した識別子で、コレクションは見ません。同じ Id を共有する対として locator と一緒に使います。デフォルトの ?photo=3 のインデックスギャラリーなら ...urlIndexKey(() => images.length) を展開し、ギャラリーが並べ替えられてもブックマークが保たれるようにするなら独自のもの（base64、スラッグ）を用意します。毎回読まれるので、次のデコードやエンコードは最新の描画の codec が担当します。 |
| `locator` | `{ locate(id) => number \| null; locateAsync?(id) => Promise<number \| null>; identify(index) => id }` | 必須 | 識別子を位置に対応させ、その妥当性を自分で判断します：locate（同期）、locateAsync（ページングされたギャラリー向けの非同期フォールバック）、identify（書き込み）。単純なインデックスのギャラリーなら ...urlIndexKey(() => images.length) を展開します。この locator と対応する codec を提供し、?photo=3 を現在の件数で制限するので、古い ?photo=99 は指されていないスライドを開く代わりに URL から取り除かれます。ページングされたフィードや識別子で指すギャラリーは、代わりに独自の codec と locator の対を用意します。毎回読まれるので、次の検索には最新の描画の locator が答え、描画のあいだに locateAsync を追加または削除すると、次に見つからなかったときから反映されます。 |

### useReactRouterUrlAdapter [#usereactrouterurladapter]

React Router に連動した `UrlAdapter` です。ルーターを使うアプリで `useOverlayUrlState` の `adapter` オプションに渡すと、ナビゲーションの信頼できる情報源がルーターだけに保たれます。ルーターの裏で `history.pushState` を書くと、その位置情報が古くなり、次のナビゲーションでパラメーターが消えます。書き込むのはクエリだけなので、パス名とハッシュはそのまま残ります。変更のたびに、ルーターが同じページで push したのか、replace したのか、履歴をたどったのかを報告するので、`<Link>` から開いたギャラリーは 1 回戻るだけで閉じます。

独自のサブパスから提供されるので、ルーターを使わないアプリのバンドルに `react-router-dom` が入ることはありません。`react-router-dom` は任意の peer dependency です。

## アクセシビリティ [#accessibility]

`<Reel>` は `aria-roledescription="carousel"` を持つ `role="region"` として描画されます。`ariaLabel` プロップを指定すると、スクリーンリーダー向けの名前が付きます。控えめなライブリージョンが、カルーセルを再レンダリングせずに、スライドが変わるたびに「Slide N of M」と読み上げます。非アクティブなスライドには `inert` 属性が付くので、フォーカスや支援技術での移動では飛ばされます。

`<ReelIndicator>` は、ドットにローミング tabindex を持つ `role="tablist"` として描画されます。矢印キーでフォーカスが移動し、Enter か Space でスライドが有効になります。

`<Reel>` を囲む独自のモーダルを作るなら、フォーカスを戻したり閉じ込めたりするために `captureFocusForReturn`、`createFocusTrap`、`getFocusableElements` が `@reelkit/react` から再エクスポートされています。
