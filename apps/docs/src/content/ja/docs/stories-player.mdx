## URL の状態 [#url-state]

<DemoLink href="https://react-demo.reelkit.dev/stories-player-url?utm_source=docs">ライブデモを見る →</DemoLink>

`StoriesUrlOverlay` は、開閉状態をアドレスバーに持つ別のコンポーネントです。2 つの軸が 1 つのパラメーター（`?story=<group>.<story>`）に乗るので、再生中のストーリーに、共有でき、ブックマークでき、戻るボタンで閉じられるリンクが付きます。`useOverlayUrlState` と `urlIndexTwoAxisKey` でコントローラーを作り、`controller` として渡します。

<Callout type="info" title="組み込みのキー">
  ストーリーは二軸なので、二軸のキーをコントローラーに展開します。`urlIndexTwoAxisKey`（グループとストーリーを位置で指す）か `urlStableIdTwoAxisKey`（グループを安定した `id` で指す）で、どちらも `@reelkit/react` から再エクスポートされています。[URL の状態のガイド](/docs/core/guide#url-state) と [Core API](/docs/core/api#url-state) を参照してください。
</Callout>

<CodeBlock code={urlState} language="tsx" />

- 開くと履歴エントリーを **1 つ** 積みます。ストーリーのスワイプ *も* ユーザーの切り替えもそれを **置き換え** るので、N 回移動してもエントリーは増えず、1 回戻れば必ずプレイヤーが閉じます。戻るとプレイヤーが閉じ、ストーリーは戻りません。
- **内側の移動も運ばれます。** ストーリーのインデックスはグループ単位で固定されず、ユーザーのストーリー内で進むと `?story=2.`*n* が更新されるので、ディープリンクは正確なストーリーに着きます。
- 戻るで閉じるのは、アプリ内から開いた場合だけです（リンクがエントリーを積んだ場合）。新しいタブで直接開いた共有リンクには前の履歴がないので、ブラウザーの戻るではサイトを離れます。✕ ボタンか Escape なら、その場でパラメーターを取り除いてページにとどまります。
- どのグループやストーリーも指さないパラメーター（古いブックマーク、手で書き換えた値、グループの末尾を超えたストーリー）は、隣を開くのではなく URL から取り除かれます。

**ルーターを使うアプリでは、アダプターを渡します。** ルーターの裏で `history.pushState` を書くと、その位置情報が古くなり、次のナビゲーションでパラメーターが消えます：

**安定したリンク。** グループはデフォルトで位置なので、ブックマークした `?story=2.0` はフィードが並べ替えられると別のユーザーを開きます。代わりにグループを安定した id で指してください。`outerCodec` が id を URL に書き、`outerLocator` がその場所を探します。`innerCodec` を `innerLocate` と `innerIdentify` と一緒に渡すと、グループ内のストーリーにも同じことができます。省略すると、ストーリーの側は単純なローカルのインデックスのままです。

**無限フィード。** ページングは codec とは関係なく、`outerLocator` の役目です。`locate` は同期なので、読み込み済みのグループにしか答えません。20 件を読み込んだフィードの 400 番目のグループへの共有リンクは見つかりません。`locateAsync` はフォールバックで、`locate` が見つけられなかったときだけ呼ばれます。ストーリーは、最終的に決まったグループの範囲に合わせて改めて制限されます。

<Callout type="info" title="同じ locateAsync を外側の軸で">
  これは一軸のキーが受け取るのと同じ `locateAsync` のページャーです。二軸のキーでは渡した `outerLocator` に乗るので、グループの軸がページングされ、ストーリーは解決されたグループ内のローカルなインデックスのままです。
</Callout>

<CodeBlock code={urlState4} language="tsx" />

- `locateAsync` が保留中のあいだ、プレイヤーは閉じたままで、パラメーターはそのまま残るので、ディープリンクは取得のあいだも失われません。`null` か reject でパラメーターは取り除かれます。
- URL が変わったあと、閉じたあと、アンマウントしたあとに届いた答えは破棄されます。遅い取得が、誰も求めていないストーリーを開くことはありません。
- `useOverlayUrlState` のすべてのオプションは [React API リファレンス](/docs/react/api#useoverlayurlstate) に、手順は [React ガイド](/docs/react/guide#url-state) にあります。

## 見たところを覚えておく [#remembering-what-was-seen]

リングは、グループを最後まで見るまでグラデーションを表示し、グループは閲覧者がまだ見ていない最初のストーリーから開きます。どちらも 1 つの `createStoriesViewedStateController` によるものです。フィードを持つ場所で一度だけ作成し、`viewed` としてリング一覧とプレイヤーに渡すと、ストアの読み取り、追従、表示したものの記録をコンポーネント側が行います。保存されたエントリーは作成者とストーリーを id で記録するため、フィードが並べ替えられても残り、同じコントローラーが Vue と Angular でも使えます。

<CodeBlock code={rememberingWhatWasSeen} language="tsx" />

- **最初のストーリーも数えます。** 画面にすでに表示されているストーリーはマウント時に既読として報告されるので、ストーリーが 1 つだけのグループは開いて閉じれば見たことになります。
- **スワイプで進んでも続きから再開します。** `resumeStoryIndex` は、このセッションで初めて到達したすべてのグループ（プレイヤーが開いたグループも含む）で参照されます。ただし `initialStoryIndex` がストーリーを直接指定している場合は別です。すでにスワイプで通過したグループは、離れたところから再び開きます。
- **リンクが優先されます。** `StoriesUrlOverlay` では、何が保存されていても、プレイヤーがどこで開くかはパラメーターが決めます。それ以外では再開のコールバックが決めます。
- **件数は合計ではなく位置です。** エントリーが表すのは到達したいちばん先のストーリーなので、見終えたグループにストーリーを追加するとリングがまた点灯し、途中から削除すると件数が減ります。共有リンクと同じ自己修復です。
- **ストレージは差し替えられます。** タブを閉じたら忘れるには `storage: createSessionStorageAdapter()` を、ほかには独自の `StorageAdapter` を渡してください。開いている 2 つのタブは、ブラウザーの storage イベントで同期します。
- **開く瞬間にだけマウントされるプレイヤーは、読み取りが遅すぎます。** プレイヤーは、まだ閉じている間に動くエフェクトでストアを読み取ります。`{open && <StoriesOverlay … />}` ではその機会がないので、dispose を返すエフェクトの中で自分で `viewed.attach()` を呼んでください。オプションと、土台になっている低レベルの部品は [Stories Core](/docs/stories-core#viewed-controller) のページにあります。

## デスクトップのカルーセル [#desktop-carousel]

`desktopLayout="carousel"` を指定すると、プレーヤーが Instagram のウェブ版のようなレイアウトになります。アクティブなストーリーはいつもの大きさのまま中央に置かれ、その左右に隣のグループが最大 2 つずつ、小さく暗めのカードとして並びます。カードをクリックするとそのグループが開き、グループが切り替わる間カードが横へスライドします。リング一覧に渡すのと同じ `viewed` コントローラーを渡すと、見終えたグループのカードは控えめなリングになります。カードが自分でそれに追従するため、ストーリーが既読になったときに再描画されるのはカードだけで、プレーヤーは再レンダリングされません。

<CodeBlock code={desktopCarousel} language="tsx" />

- **スマートフォンでは通常のプレーヤーのままです。** 幅 768px までならカードは描画されず、スワイプにはデフォルトの `'single'` レイアウトと同じく `groupTransition` が使われます。ウィンドウの幅がこの境目をまたぐと、その場でレイアウトが切り替わります。
- **カードにはグループが開く位置が表示されます**：このセッションで離れたときのストーリー、なければ `resumeStoryIndex` が返すストーリーです。動画のポスターか画像そのものを表示します。どちらもないストーリー（グラデーション上のテキストのストーリーなど）は、`renderSlide` がプレーヤーの大きさで描き、それを縮小して表示します。ポスターのない動画ではカードの背景が見えます。このプレビューは `renderSlide` を `isActive: false` で呼び出す、ただの画像です。中の要素にフォーカスもクリックも届きません。再生やアナリティクスなど、スライドがマウント時に行う処理は `isActive` のときだけ実行してください。
- **タイマーはスライドを待ちます。** カードの動きが止まるまで、ストーリーは進まず、そのストーリーの `onStoryViewed` も呼ばれません。
- **グループを切り替えるどの方法でもスライドします**：カードのクリック、`StoriesApi.goToGroup`、`nextGroup` と `prevGroup`、そしてグループの最後を越える矢印キーです。タッチのスワイプはプレーヤー自体を動かすので、その上にスライドは重なりません。

## グループごとの進捗バーとヘッダー [#chrome-placement]

デフォルトでは、進捗バーとヘッダーが 1 つずつプレーヤーの上にあり、グループが切り替わった後で新しいグループの表示に変わります。`chromePlacement="group"` を指定すると、各グループが自分のスライドの中に専用の進捗バーとヘッダーを持ち、Instagram と同じようにグループと一緒に回転します。

<CodeBlock code={chromePlacement} language="tsx" />

- **隣のグループは、どこまで見たかを表示します。** プレーヤーがそのグループへ回転している間、進捗バーとヘッダーは、そのグループが開くストーリーを、まだ何も再生していない状態で表示します。
- **離れていくグループはそのままの状態を保ちます。** 回転が終わるまで進捗バーはそれまでの進み具合を保つので、最後まで見たグループは回転の途中で空にならず、満たされたままです。
- **独自のレンダラーは画面上のグループそれぞれに対して呼ばれます。** `renderProgressBar` と `renderHeader` は `groupIndex` と `isActive` を受け取ります。隣のグループでは `isActive` が `false` になり、進捗のシグナルは変化しません。
- **独自のヘッダーはスワイプ領域の中にあります。** ヘッダーをタップするとストーリーが切り替わります。ただし `button`、リンク、`role="button"` を持つ要素の上なら切り替わらないので、ヘッダー内の操作要素はすべてそのいずれかにしてください。
- **デスクトップのカルーセルでは、スライド中の見た目は変わりません。** カードがスライドしている間はプレーヤーが隠れるため、この設定はグループが開いてから反映されます。

## コンテンツ読み込みのライフサイクル [#content-loading-lifecycle]

各ストーリーのスライドは、`SlideRenderProps` を通じて渡されるコールバックで読み込み状態を伝えます：

| コールバック | タイミング |
| --- | --- |
| `onReady` | コンテンツの準備ができた（画像が読み込まれた、動画が再生中）。進捗のタイマーが始まります。 |
| `onWaiting` | コンテンツが止まった（再生の途中で動画がバッファリング中）。スピナーが表示され、タイマーが止まります。 |
| `onError` | コンテンツの読み込みに失敗した。エラーのオーバーレイが表示されます。 |
| `onDurationReady` | メディアの実際の長さ（たとえば動画のメタデータから）を報告し、正しい長さでタイマーを再開します。 |
| `onEnded` | メディアが終わった（たとえば動画が最後まで再生された）ことを伝えます。次のストーリーへ進みます。 |

<Callout type="info" title="プリローダーのキャッシュ">
  組み込みの `ImageStorySlide` と `VideoStorySlide` コンポーネントは、次のストーリーをバックグラウンドで先読みします。先読み済みのストーリーへ移動すると、読み込みのスピナーなしで内容がすぐに表示されます。
</Callout>

| 元のパッケージ | 再エクスポートされるもの |
| --- | --- |
| `@reelkit/react` | `SoundProvider`、`useSoundState`、`useOverlayUrlState`、`createViewedStateController`、`twoAxisViewedTracking`、`createLocalStorageAdapter`、`createSessionStorageAdapter`、`createMemoryStorageAdapter`、`urlIndexTwoAxisKey`、`urlStableIdTwoAxisKey`、`base64UrlCodec`、および型 `UrlAdapter`、`UrlCodec`、`UrlLocator`、`UrlKey`、`UrlStateController`、`TwoAxisPosition`、`TwoAxisIdentity`、`UrlIndexTwoAxisKeyOptions`、`ViewedStateController`、`ViewedStateOptions`、`StorageAdapter` |

`SoundProvider` と `useSoundState` は、プレイヤーがスライドと共有するサウンドの状態を運びます。自分でメディアを再生するカスタムスライドは、`useSoundState` を通してミュートの切り替えを読み取ります。プレイヤーの中ではすでにプロバイダーが置かれています。それ以外の場所で描画する `VideoStorySlide` やカスタムスライドには、上に `SoundProvider` が必要で、ないと `useSoundState` が例外を投げます。

## アクセシビリティ [#accessibility]

オーバーレイのルートはモーダルダイアログ（`role="dialog"`、`aria-modal="true"`）です。`ariaLabel` を指定すると、スクリーンリーダーの読み上げが変わります。デフォルトは「Stories player」です。

オーバーレイは開くとフォーカスを取り込み、閉じるとトリガーに戻します。Tab と Shift+Tab は中のフォーカス可能な要素を循環し、外へ出たフォーカス（外側のクリック、プログラムからのフォーカス）は引き戻されます。`@reelkit/core` の `captureFocusForReturn` と `createFocusTrap`（`@reelkit/react` が再エクスポート）で実装されています。

デスクトップのカルーセルでは、デフォルトのカードはそれぞれ「Open stories by」と作成者名のラベルを持つボタンです。カードは Tab の順序でプレーヤーの操作ボタンのあとに来て、スライドの間はその順序から外れます。

## サーバーサイドレンダリング [#server-side-rendering]

オーバーレイは閉じている間は何も描画せず、開いたときに初めて `document.body` にポータルします。これはクライアントで起こります。`StoriesUrlOverlay` はマウント後のエフェクトでアドレスバーを読むので、サーバーでの描画で開くことはありません。`StoriesRingList` はサーバーではすべてのリングを未視聴として描画します。視聴済みのストアはマウント後にしか読まれないため、サーバーのマークアップとクライアントの最初の描画が一致します。全体像は [SSR ガイド](/docs/ssr) を参照してください。

## キーボードショートカット [#keyboard-shortcuts]

| キー | 動作 |
| --- | --- |
| `ArrowLeft` | 前のストーリー。グループの最初のストーリーでは前のグループへ移り、離れたときのストーリー（なければ再開位置のストーリー）を開きます。最初のグループでは何もしません |
| `ArrowRight` | 次のストーリー。グループの最後のストーリーを過ぎると次のグループへ移り、最後のグループを過ぎるとプレイヤーが閉じます |
| `Escape` | プレイヤーを閉じる |
