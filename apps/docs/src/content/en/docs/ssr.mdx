All reelkit packages work on the server. Import and render them with Next.js, Remix, Angular SSR, Nuxt 3, or any SSR setup.

## How It Works [#how-it-works]

The core slider controller is pure logic with no DOM access at construction. Gesture listeners, keyboard events, and animations attach only in client-side lifecycle hooks.

<FrameworkVariant for="react">

During SSR, the React `Reel` renders a static container with the initial visible slides (typically 3: previous, current, next) when it has a `size`, and an empty container when it measures itself. On hydration, it attaches gesture, keyboard, and wheel controllers to make everything interactive.

</FrameworkVariant>

<FrameworkVariant for="vue">

The Vue `Reel` renders an empty container on the server and draws its slides after hydration. With a `size`, that container does not match what the client renders first, so in Nuxt it goes inside `<ClientOnly>` (see [Nuxt 3](#nuxt-3)).

</FrameworkVariant>

## Responsive Size with SSR [#responsive-size-with-ssr]

Omit the `size` prop entirely. When `size` is not provided, Reel auto-measures its container via `ResizeObserver` on the client. During SSR the slider renders an empty container; on hydration it measures and renders slides immediately:

<CodeBlock code={nextAutoSize} language="tsx" />

<Callout type="info" title="How auto-size works">
  When `size` is omitted, the container must be sized by CSS (parent flex/grid, explicit width/height, or percentages). The slider renders nothing until the first measurement completes, then fills the measured dimensions and responds to subsequent resizes automatically.
</Callout>

### Explicit size (manual approach) [#explicit-size-manual-approach]

For pixel-level control, pass an explicit `size` prop. Since `window.innerWidth` is not available during SSR, provide a default and update on mount:

<CodeBlock code={nextExplicitSize} language="tsx" />

<Callout type="info" title="Tip">
  Choose a default size that matches your most common viewport (e.g. mobile-first). The slider will re-adjust instantly on hydration if the actual viewport differs.
</Callout>

## Nuxt 3 [#nuxt-3]

ReelKit Vue components import and render on the server without errors. `Reel` sends an empty container from the server and draws its slides after hydration. When `Reel` measures itself, that container hydrates cleanly from `@reelkit/vue` 0.9.1; earlier versions kept it at zero height, so no slides appeared. With an explicit `size`, the client's first render already has slides, which gives a hydration mismatch. In that case, or on an earlier version, wrap `Reel` in a `<ClientOnly>` component or use the `.client.vue` suffix:

## Responsive Size with SSR [#responsive-size-with-ssr]

Omit the `size` prop to use auto-measurement. The Reel auto-sizes to 100% of its parent and, from `@reelkit/vue` 0.9.1, needs no `<ClientOnly>`: the server sends an empty container at full size, and the client measures it and renders slides. The example keeps the wrapper, which also works on earlier versions:

## Overlay Components [#overlay-components]

`ReelPlayerOverlay`, `LightboxOverlay` and `StoriesOverlay` render nothing when `isOpen` is false, so they need no `<ClientOnly>` and produce no markup during server rendering. They teleport their content to the body only once opened on the client.

</FrameworkVariant>

## Summary [#summary]

<Callout type="success" title="What works out of the box">
  - Importing any reelkit package on the server
  - Rendering slider components during SSR (produces valid static HTML)
  - Creating controllers on the server
  - Overlay components when `isOpen=false`
</Callout>

<Callout type="warning" title="What to keep in mind">
  - Omit `size` for auto-measurement, or provide a default when using viewport-based dimensions
  - In Nuxt, render the Vue `Reel` inside `<ClientOnly>` when it has a `size`, or on `@reelkit/vue` before 0.9.1
  - Don't call `attach()`/`observe()` on the server when using core directly
</Callout>
