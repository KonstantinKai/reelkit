## Reel Component [#reel-component]

The `Reel` component is the main container that manages slider state, handles touch gestures, keyboard navigation, and animations.

Only three slides are ever in the DOM, the current one and its neighbours, so a list of ten thousand items costs the same as a list of ten. To see it working in a whole feature, an infinite feed or a grid that opens a player, go to the [Recipes](/docs/recipes).

## Auto-sizing [#auto-sizing]

The `size` prop is optional. When omitted, Reel auto-measures its container via `ResizeObserver` and adapts to CSS-driven layout. The container must be sized by its parent (e.g. flex, grid, or explicit CSS dimensions).

## URL State [#url-state]

`useOverlayUrlState` builds a URL-state controller for an overlay and returns it whole, then you hand it to a `*UrlOverlay` as its `controller` prop. The URL owns the open state, so a bound overlay opens itself and a link is the usual open action. The first write of an absent parameter pushes one history entry and every write after replaces it, so paging never buries the back button. Keep the controller to read `value`/`position` and to drive it programmatically: `set(position)` opens, `set(null)` closes, and `set` is the same low-level write the overlay uses internally on slide change.

<CodeBlock code={urlState} language="tsx" />

The options object takes `param`, `codec`, and `locator` (all three required), plus an optional `adapter`. `param` and `adapter` are read on the first render and fixed after that — remount to change them — while `codec` and `locator` are read live, so a lookup after the list grew or reordered sees the current list. The `codec` and `locator` are a matched pair sharing the same `Id`, so they travel together — for a plain `?photo=3` gallery spread `...urlIndexKey(() => images.length)`, which returns both halves at once. `urlIndexKey` maps the parameter to a slide index and bounds it against the live count the getter returns, so a stale or out-of-range `?photo=99` is rejected and heals itself out of the URL instead of opening a slide that was never named. Pass a getter, not a number, so the bound stays right as a paginated feed grows. It wraps `createIndexLocator` (the locator half) and pairs it with `indexCodec`. A paginated feed or an identity-keyed gallery supplies its own matched `codec` + `locator` instead. The full options table lives on the [React API reference](/docs/react/api#useoverlayurlstate).

## Performance Tips [#performance-tips]

<KeyPoints>
<KeyPoint title="Memoize data arrays">
  Wrap your items array with `useMemo`. A new array reference on every render triggers a `count` update and re-computation of visible ranges.
</KeyPoint>
<KeyPoint title="Keep itemBuilder lightweight">
  It runs on every visible range change (typically 3 slides). Avoid heavy computation or side effects inside it.
</KeyPoint>
<KeyPoint title="Load data near the edge">
  Use `afterChange` to detect when the user approaches the end and fetch the next batch before they run out of slides (see the [Infinite Feed](/docs/recipes/infinite-feed) recipe).
</KeyPoint>
<KeyPoint title="Disable wheel in scrollable pages">
  Set `enableWheel={false}` when the slider is embedded in a scrollable layout to avoid capturing the page scroll.
</KeyPoint>
</KeyPoints>
