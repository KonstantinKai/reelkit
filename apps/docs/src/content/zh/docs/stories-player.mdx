## URL 状态 [#url-state]

<DemoLink href="https://react-demo.reelkit.dev/stories-player-url?utm_source=docs">查看在线演示 →</DemoLink>

`StoriesUrlOverlay` 是一个独立组件，它的打开状态存放在地址栏里。两条轴共用一个参数 —— `?story=<group>.<story>` —— 于是正在播放的 story 就有了可分享、可收藏、能用返回键关闭的链接。用 `useOverlayUrlState` 和 `urlIndexTwoAxisKey`构建控制器，再作为 `controller`.

<Callout type="info" title="内置的 key">
  Stories 是双轴的，所以请把双轴 key 展开进控制器： `urlIndexTwoAxisKey` （分组和 story 都按位置）或 `urlStableIdTwoAxisKey` （分组按稳定的 `id`）—— 两者都从 `@reelkit/react`. See the [URL 状态指南](/docs/core/guide#url-state) 和 [核心 API](/docs/core/api#url-state).
</Callout>

<CodeBlock code={urlState} language="tsx" />

- 打开时压入 **一条** 历史记录。滑动 story *和* 切换用户都是 **替换** 它，因此导航 N 次也不会多出记录，退一步永远就是关闭播放器。返回键关闭播放器，不会逐个后退 story。
- **内层导航也会被记录。** story 索引不会被冻结在分组粒度上 —— 在某个用户的 story 之间前进时会更新 `?story=2.`*n* ，因此深链能精确落到那一个 story。
- 只有在应用内部打开播放器时返回键才会关闭它 —— 因为那次链接压入了一条记录。在新标签页里直接打开的分享链接背后没有历史，浏览器返回会离开站点；这时用 ✕ 按钮或 Escape 就地移除参数并留在页面上。
- 指向不存在的分组或 story 的参数 —— 过期的书签、手改的值、超出分组末尾的 story —— 会从 URL 中移除，而不是打开相邻的那个。

**带路由的应用 —— 请传入适配器。** 绕过路由器直接写 `history.pushState` 会让它的 location 过期，下一次导航就会把参数丢掉：

<CodeBlock code={urlState2} language="tsx" />

**稳定的链接。** 分组默认是按位置的，所以收藏下来的 `?story=2.0` 在信息流重新排序后就会打开另一个用户。请改用稳定 id 来寻址分组 —— `outerCodec` 把 id 写进 URL， `outerLocator` 负责找到它在哪。story 那一半仍然是解析出的分组内的普通索引。

<CodeBlock code={urlState3} language="tsx" />

**无限信息流。** 翻页是 `outerLocator` 该管的事，与编解码器无关。 `locate` 是同步的，因此只能回答已经加载过的分组 —— 只加载了 20 个时，指向第 400 个分组的分享链接就查不到。 `locateAsync` 是兜底，只有在 `locate` 未命中时才调用；story 会以最终落到的那个分组重新校准上界。

<Callout type="info" title="同一个 locateAsync，作用在外层轴">
  这和单轴 key 接受的 `locateAsync` 翻页器是同一个 —— 在双轴 key 上它跟随你传入的 `outerLocator` ，因此分组这条轴负责翻页，而 story 仍是解析出的分组内的局部索引。
</Callout>

<CodeBlock code={urlState4} language="tsx" />

- 在 `locateAsync` 未完成期间，播放器保持关闭，参数也不动，因此深链能熬过这次请求。返回 `null` 或请求被拒绝则会移除参数。
- 如果结果在 URL 已经变化、播放器已关闭或组件已卸载之后才到达，就会被丢弃 —— 慢请求不能打开一个没人要的 story。
- 完整的 `useOverlayUrlState` 选项见 [React API 参考](/docs/react/api#useoverlayurlstate)，完整讲解见 [React 指南](/docs/react/guide#url-state).

## 记住已观看内容 [#remembering-what-was-seen]

圆环在分组看完之前显示渐变，分组重新打开时停在观看者尚未看过的第一条 story。两者都来自同一个 `createStoriesViewedStateController`：在 feed 所在的地方创建一次，作为 `viewed` 交给圆环列表和播放器，它们会自己读取存储、跟随它并记录看过的内容。已存记录按 id 记下作者和 story，因此能经受 feed 重排，而且同一个控制器在 Vue 和 Angular 中同样可用。

<CodeBlock code={rememberingWhatWasSeen} language="tsx" />

- **打开时的 story 也算。** 挂载时就把屏幕上的 story 报告为已看，所以打开只有一条 story 的分组再关闭，也会标记为已看。
- **往后滑同样会续播。** `resumeStoryIndex` 对本次会话中第一次到达的每个分组生效，包括播放器打开时所在的那个，除非 `initialStoryIndex` 显式指定了 story；已经滑过的分组会在离开处重新打开。
- **链接仍然优先。** 使用 `StoriesUrlOverlay` 时，由参数决定播放器在哪里打开，无论存了什么。其他情况下由续播回调决定。
- **计数是位置，不是次数。** 记录记的是到达的最远一条 story，因此给已看完的分组新增一条会重新点亮圆环，从中间删掉一条则会让计数变短。与分享链接得到的自愈相同。
- **存储可替换。** 传入 `storage: createSessionStorageAdapter()` 在关闭标签页时遗忘，或使用自己的 `StorageAdapter`。两个打开的标签页通过浏览器的 storage 事件保持一致。
- **只在打开时才挂载的播放器读取得太晚。** 播放器在一个效果中读取存储，而该效果在它仍然关闭时就已运行。使用 `{open && <StoriesOverlay … />}` 时没有这个时机，所以请自己在一个返回其 dispose 的效果中调用 `viewed.attach()`。各选项以及它所基于的底层部件，见 [Stories Core](/docs/stories-core#viewed-controller) 页面。

## 桌面端轮播 [#desktop-carousel]

设置 `desktopLayout="carousel"`，播放器就会像 Instagram 网页版那样布局：当前故事保持原有尺寸居中，两侧各最多显示两个相邻分组，以较小、变暗的卡片呈现。点击卡片会打开对应分组，切换分组时卡片会横向滑动。传入与头像环列表相同的 `viewed` 控制器，已看完分组的卡片就会显示灰色的环。卡片会自行跟随它，因此故事被标记为已看时只有卡片重绘，播放器不会重新渲染。

<CodeBlock code={desktopCarousel} language="tsx" />

- **手机上仍是普通播放器。** 宽度不超过 768px 时不渲染卡片，滑动使用 `groupTransition`，与默认的 `'single'` 布局一致。窗口宽度跨过这个值时布局会即时切换。
- **卡片预览分组将要打开的位置**：本次会话中离开时所在的故事，否则是 `resumeStoryIndex` 返回的故事。卡片显示视频封面或图片本身。两者都没有的故事（例如渐变背景上的文字故事）会由你的 `renderSlide` 按播放器尺寸绘制后再缩小；没有封面的视频显示卡片背景。这个预览以 `isActive: false` 调用 `renderSlide`，只是一张图：其中的任何内容都无法获得焦点或被点击。幻灯片在挂载时做的事情（例如播放或统计）请放在 `isActive` 判断之后。
- **计时器会等滑动结束。** 卡片停止移动之前，故事不会前进，也不会为它触发 `onStoryViewed`。
- **所有切换分组的方式都会滑动**：点击卡片、`StoriesApi.goToGroup`、`nextGroup` 和 `prevGroup`，以及在分组末尾继续按方向键。触摸滑动本身已经移动了播放器，因此不会再叠加滑动。

## 每个分组自带进度条和页眉 [#chrome-placement]

默认情况下，播放器上方只有一个进度条和一个页眉，分组切换完成后才换成新分组的内容。设置 `chromePlacement="group"` 后，每个分组都在自己的幻灯片里拥有一份，二者会像 Instagram 那样随分组一起转动。

<CodeBlock code={chromePlacement} language="tsx" />

- **相邻分组显示它停在哪里。** 播放器转向它时，它的进度条和页眉显示它将打开的那个 story，尚未播放任何部分。
- **正在离开的分组保持原样。** 它的进度条在转动结束前保留原有进度，所以一个已播完的分组会保持填满，而不会在转动中途清空。
- **屏幕上的每个分组都会调用自定义渲染器。** `renderProgressBar` 和 `renderHeader` 会收到 `groupIndex` 和 `isActive`；对相邻分组，`isActive` 为 `false`，进度信号保持不变。
- **自定义页眉位于滑动区域内。** 点击它会切换 story，除非点在 `button`、链接或带 `role="button"` 的元素上，所以其中的每个控件都应是这几类元素之一。
- **桌面端轮播在滑动过程中不受影响。** 卡片滑动时播放器是隐藏的，因此这个选项在分组打开后才会显现。

| `innerTransitionDuration` | `number` | 200 | 内层（story）过渡动画的时长（毫秒） |
| `minSegmentWidth` | `number` | 8 | 进度条分段的最小宽度（像素） |
| `apiRef` | `MutableRefObject<StoriesApi \| null>` | - | 用于访问命令式 StoriesApi 的 ref |
| `desktopLayout` | `'single' \| 'carousel'` | 'single' | 桌面端布局。'carousel' 在当前故事两侧以预览卡片显示相邻分组，并在分组之间滑动。手机上始终只显示故事本身。类型以 `DesktopLayout` 导出。 |
| `chromePlacement` | `'overlay' \| 'group'` | 'overlay' | 进度条和页眉放在哪里。'overlay' 在播放器上方绘制一份；'group' 在每个分组的幻灯片里各绘制一份，二者随分组一起转动。类型以 `ChromePlacement` 导出。 |
| `viewed` | `StoriesViewedStateController` | - | 观看者已看过的内容，来自 createStoriesViewedStateController()。分组从第一个未看的 story 续播，每个显示过的 story 都会被记录，轮播卡片会为看完的分组显示灰色的环。把同一个控制器交给 StoriesRingList。 |
| `renderHeader` | `(props: HeaderRenderProps<T>) => ReactNode` | - | 自定义页眉渲染器。接收作者、story 以及暂停 / 静音状态。使用 `chromePlacement="group"` 时页眉位于滑动区域内，参见[每个分组自带进度条和页眉](/docs/stories-player#chrome-placement)。 |
| `renderFooter` | `(props: FooterRenderProps<T>) => ReactNode` | - | 自定义页脚渲染器。接收作者和 story 信息。 |
| `renderSlide` | `(props: SlideRenderProps<T>) => ReactNode` | - | 自定义幻灯片渲染器，替换默认的图片 / 视频幻灯片。 |
| `renderNavigation` | `(props: NavigationRenderProps) => ReactNode` | - | 自定义桌面端导航。替换默认的上一张 / 下一张箭头按钮。 |

### StoriesUrlOverlayProps [#storiesurloverlayprops]

| 属性 | 类型 | 默认值 | 说明 |

## 内容加载生命周期 [#content-loading-lifecycle]

每个 story 幻灯片都通过 `SlideRenderProps`:

| 回调 | 何时 |
| --- | --- |
| `onReady` | 内容就绪（图片已加载、视频在播放）。进度计时开始。 |
| `onWaiting` | 内容卡住（视频播放途中缓冲）。显示转圈动画并暂停计时。 |
| `onError` | 内容加载失败。显示错误浮层。 |
| `onDurationReady` | 上报媒体的真实时长（例如来自视频元数据），以便用正确的时长重启计时。 |
| `onEnded` | 表示媒体已播完（例如视频结束）。会前进到下一个 story。 |

<Callout type="info" title="预加载缓存">
  内置的 `ImageStorySlide` 和 `VideoStorySlide` 组件会在后台预加载下一个 story。用户切到已预加载的 story 时，内容会立刻出现，不会有加载动画。

## 无障碍 [#accessibility]

浮层根节点是一个模态对话框（`role="dialog"`, `aria-modal="true"`）。设置 `ariaLabel` 可以改变屏幕阅读器的播报内容，默认是 “Stories player”。

浮层打开时捕获焦点，关闭时把焦点还给触发元素。Tab 和 Shift+Tab 在内部的可聚焦元素之间循环；跑出去的焦点（点击外部、程序化聚焦）会被拉回来。实现基于 `captureFocusForReturn` 和 `createFocusTrap` from `@reelkit/core`.

在桌面端轮播中，每张默认卡片都是一个按钮，标签为 “Open stories by” 加上作者名。卡片在 Tab 顺序中排在播放器控件之后，滑动进行时会暂时移出 Tab 顺序。
