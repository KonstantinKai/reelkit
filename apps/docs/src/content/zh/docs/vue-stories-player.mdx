## URL 状态 [#url-state]

<DemoLink href="https://vue-demo.reelkit.dev/stories-player-url?utm_source=docs">查看在线演示 →</DemoLink>

`StoriesUrlOverlay` 是一个独立组件，它的打开状态存放在地址栏里。两个轴共用一个参数 —— `?story=<group>.<story>` —— 因此正在播放的故事有一个可分享、可收藏、可用后退按钮关闭的链接。用 `useOverlayUrlState` 和 `urlIndexTwoAxisKey` 创建控制器，然后作为 `controller` 传入。

<Callout type="info" title="内置 key">
  故事是双轴的，所以要把双轴 key 展开到控制器里：`urlIndexTwoAxisKey`（按位置定位用户和故事）或 `urlStableIdTwoAxisKey`（用户按稳定 `id` 定位）—— 两者都从 `@reelkit/vue-stories-player` 重新导出。参见 [URL 状态指南](/docs/core/guide#url-state)和 [Core API](/docs/core/api#url-state)。
</Callout>

<CodeBlock code={urlState} language="vue" />

- 打开会压入**一条**历史记录。在故事之间移动*以及*切换用户都只是**替换**它，因此 N 次导航不会新增记录，一次后退始终关闭播放器。后退是关闭，而不是回到上一条故事。
- **内层导航也会写进 URL。** 在同一用户的故事间前进会把 `?story=2.`*n* 更新掉，因此深层链接能落到确切的那条故事。
- 只有当播放器是在应用内部打开时，后退才会关闭它 —— 那次跳转压入了一条记录。直接在新标签页打开的分享链接背后没有历史记录，后退会离开站点；✕ 按钮或 Escape 会就地移除参数并留在页面上。
- 指向不存在的用户或故事的参数 —— 过期书签、手改的值、超出该用户故事数量的序号 —— 会从 URL 中移除，而不是打开相邻的一条。
- 使用路由的应用应该传入基于路由器的适配器，让路由器始终是导航状态的唯一来源。`@reelkit/vue/vue-router-url-adapter` 中的 `useVueRouterUrlAdapter` 就是 Vue Router 的现成适配器；绕过路由器直接写历史会让它的 location 过期，下一次导航就会丢掉参数。

**稳定链接。** 用户默认按位置定位，因此收藏的 `?story=2.0` 在信息流重新排序后会打开另一个人。改用稳定 id 定位用户 —— `outerCodec` 负责把 id 写进 URL，`outerLocator` 负责找到它所在的位置。同时传入 `innerCodec` 以及 `innerLocate` 和 `innerIdentify`，就能对分组内的故事做同样的事；不传的话，故事那一半仍然是已解析分组内部的普通索引。故事 id 不能包含 `.`，它是两半之间的分隔符。

<CodeBlock code={urlState2} language="typescript" />

**无限信息流。** 分页属于 `outerLocator` 的职责，与编解码器无关。`locate` 是同步的，只能回答已加载的分组 —— 指向第 400 个分组、而只加载了 20 个的分享链接会落空。`locateAsync` 是兜底，只在 `locate` 未命中时调用；故事随后会按最终落到的那个分组重新约束。

<Callout type="info" title="同一个 locateAsync，外层轴">
  这与单轴 key 接受的 `locateAsync` 分页器是同一个 —— 在双轴 key 上它跟着你传入的 `outerLocator` 走，因此分页发生在用户这一轴，而故事仍是已解析分组内部的局部索引。
</Callout>

<CodeBlock code={urlState3} language="typescript" />

- 在 `locateAsync` 等待期间，播放器保持关闭且参数原样保留，因此深层链接能熬过这次请求。返回 `null` 或拒绝则会移除参数。
- 如果答复在 URL 已经变化之后、关闭之后或卸载之后才到达，就会被丢弃 —— 一次缓慢的请求无法打开没人再要求的故事。
- `useOverlayUrlState` 的完整选项见 [Vue API 参考](/docs/vue/api#useoverlayurlstate)。

## 记住看到哪里 [#remembering-what-was-seen]

在一位用户的故事被看完之前，头像环一直是渐变色；而分组会从观众还没看过的第一条故事重新打开。两者都来自同一个 `createStoriesViewedStateController`：在信息流所在的地方创建一次，作为 `viewed` 交给头像环列表和播放器 —— 它们会自己读取存储、跟随它并记录已展示的内容。存储条目用 id 记录作者和故事，因此信息流重新排序后依然有效，同一个控制器在 React 和 Angular 中也同样可用。

<CodeBlock code={rememberingWhatWasSeen} language="vue" />

- **打开时那条故事也算。** 已经显示在屏幕上的故事会在播放器挂载后被标记为已看，因此打开只有一条故事的分组再关闭，就算看完了。
- **继续往后滑同样会续播。** 本次会话中首次到达的每个分组都会询问 `resumeStoryIndex`，包括播放器最初打开的那个，除非 `initialStoryIndex` 明确指定了故事；已经滑过的分组会回到上次离开的位置。
- **链接依然优先。** 使用 `StoriesUrlOverlay` 时，无论存储了什么，都由参数决定播放器从哪里打开。其他情况下由续播回调决定。
- **计数是位置，不是总量。** 条目记录的是到达过的最远一条故事，因此给已看完的分组新增故事会让它的圆环重新亮起，从中间删掉一条则会让计数变短。
- **存储可替换。** 传入 `storage: createSessionStorageAdapter()` 可在标签页关闭时忘记，或传入你自己的 `StorageAdapter`。两个打开的标签页通过浏览器的 storage 事件保持同步。
- **只在打开时才挂载的播放器读得太晚。** 覆盖层在挂载之后、仍然关闭的状态下读取存储。用 `v-if="open"` 时没有这个时机，因此请自己在 `onMounted` 里调用 `viewed.attach()`，并在 `onUnmounted` 里调用它返回的清理函数。相关选项以及它所基于的底层构件都在 [Stories Core](/docs/stories-core#viewed-controller) 页面。

## 桌面轮播 [#desktop-carousel]

设置 `desktop-layout="carousel"`，播放器就会像 Instagram 网页版那样排布：当前故事以正常尺寸留在中间，两侧各有最多两个相邻分组作为更小、更暗的卡片。点击卡片会打开那个分组，切换分组时卡片会横向滑动。把交给头像环列表的同一个 `viewed` 控制器也传进来，已看完分组的卡片就会显示暗色圆环。卡片自己跟随它，因此某条故事被标记为已看时只有卡片重绘，播放器不会重新渲染。

<CodeBlock code={desktopCarousel} language="vue" />

- **手机上保持普通播放器。** 宽度在 768px 以内时不渲染卡片，滑动使用 `group-transition`，与默认的 `'single'` 布局一致。跨过这个宽度调整窗口会实时切换。
- **每张卡片预览该分组将要打开的内容**：本次会话中离开时的那条故事，否则是 `resumeStoryIndex` 返回的那条。它会显示视频封面或图片。两者都没有的故事（例如渐变背景上的纯文字故事）会由你的 `#slide` 插槽按播放器尺寸绘制后缩小；没有封面的视频则显示卡片背景。该预览拿到的是 `isActive: false`，它只是一张图：其中的内容无法聚焦，也无法点击。请把幻灯片挂载时会做的事情（例如播放或埋点）放在 `isActive` 判断之后。
- **计时器会等待滑动结束。** 在卡片停止移动之前，故事不会前进，`story-viewed` 也不会为它触发。
- **每一种切换分组的方式都会触发滑动**：点击卡片、`StoriesApi.goToGroup`、`nextGroup` 与 `prevGroup`，以及在分组末尾继续按方向键。触摸滑动本身已经移动了播放器，因此不会再叠加一次滑动。

## 每个分组自带进度条和头部 [#chrome-placement]

默认情况下，播放器上方只有一个进度条和一个头部，分组切换完成后才换成新分组的内容。设置 `chrome-placement="group"` 后，每个分组都在自己的幻灯片里拥有一份，二者会像 Instagram 那样随分组一起转动。

<CodeBlock code={chromePlacement} language="vue" />

- **相邻分组显示它停在哪里。** 播放器转向它时，它的进度条和头部显示它将打开的那个故事，尚未播放任何部分。
- **正在离开的分组保持原样。** 它的进度条在转动结束前保留原有进度，所以一个已播完的分组会保持填满，而不会在转动中途清空。
- **屏幕上的每个分组都会渲染这些插槽。** `#progressBar` 和 `#header` 的作用域带有 `groupIndex` 和 `isActive`；对相邻分组，`isActive` 为 `false`，进度信号保持不变。
- **`#header` 插槽位于滑动区域内。** 点击它会切换故事，除非点在 `button`、链接或带 `role="button"` 的元素上，所以其中的每个控件都应是这几类元素之一。
- **桌面端轮播在滑动过程中不受影响。** 卡片滑动时播放器是隐藏的，因此这个选项在分组打开后才会显现。

## 作用域插槽 [#scoped-slots]

八个作用域插槽可以替换播放器的任何部分。每个插槽都会收到带类型的作用域对象。没有传的插槽保持默认 —— 渲染结果为空的插槽同样如此，因此变为 false 的 `v-if` 会回退到默认，而不是留下空洞。

| 插槽 | 作用域 | 说明 |
| --- | --- | --- |
| #error | `{ story, storyIndex, groupIndex }` | 替换绘制在当前故事之上的内置「Content unavailable」面板 |

## 重新导出 [#re-exports]

使用者需要的一切都来自这个包，因此永远不必直接引入 `@reelkit/core`。

| 来源 | 重新导出的内容 |
| --- | --- |
| `@reelkit/vue` | `Observe`、`SoundProvider`、`useSoundState`、`useOverlayUrlState`、`createViewedStateController`、`twoAxisViewedTracking`、`createLocalStorageAdapter`、`createSessionStorageAdapter`、`createMemoryStorageAdapter`、`urlIndexTwoAxisKey`、`urlStableIdTwoAxisKey`、`base64UrlCodec`，以及类型 `UrlAdapter`、`UrlCodec`、`UrlLocator`、`UrlKey`、`UrlStateController`、`TwoAxisPosition`、`TwoAxisIdentity`、`UrlIndexTwoAxisKeyOptions`、`ViewedStateController`、`ViewedStateOptions`、`StorageAdapter` |

`Observe` 是播放器内部使用的渲染边界：核心信号变化时它只重新渲染自己的插槽，故事切换正是这样只刷新头部和进度条，而不重绘两个滑块。当整个组件通过 `toVueRef` 跟随信号显得过粗时，就在自定义插槽里用它 —— 参见 [Vue API 参考](/docs/vue/api#observe)。

每个组件的属性类型也都有导出：`StoriesOverlayProps`、`StoriesUrlOverlayProps`、`StoriesRingProps`、`StoriesRingListProps`、`StoryHeaderProps`、`CanvasProgressBarProps`、`ImageStorySlideProps` 和 `VideoStorySlideProps`。

## 无障碍 [#accessibility]

覆盖层根节点是模态对话框（`role="dialog"`、`aria-modal="true"`）。设置 `aria-label` 可以改变屏幕阅读器朗读的内容，默认是「Stories player」。

覆盖层在打开时捕获焦点，关闭时把焦点还给触发元素。Tab 与 Shift+Tab 在内部的可聚焦元素之间循环；跑到外面的焦点会被拉回来。实现基于 `@reelkit/core` 的 `captureFocusForReturn` 和 `createFocusTrap`，并由 `@reelkit/vue` 重新导出。

使用桌面轮播时，每张默认卡片都是一个按钮，标签为「Open stories by」加作者名。卡片在 Tab 顺序中排在播放器控件之后，滑动期间则被移出 Tab 顺序；打开自己分组的那张卡片会把焦点交还给对话框，而不是丢在页面上。

## 服务端渲染 [#server-side-rendering]

关闭状态下覆盖层什么也不渲染，`StoriesRingList` 在服务端把每个圆环都渲染成未看状态：已看存储只在挂载之后读取，因此服务端标记与首次客户端渲染一致。更完整的说明见 [SSR 指南](/docs/ssr)。
