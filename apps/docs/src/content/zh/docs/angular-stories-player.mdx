## 快速上手 [#quick-start]

`rk-stories-overlay` 渲染全屏播放器。把它和 `rk-stories-ring-list` 搭配使用，就能得到 Instagram 风格的入口：圆环会带着分组索引发出 `(selected)`，宿主把它保存为 `initialGroupIndex`，再设置 `isOpen`。播放器从不自行关闭；它发出 `(closed)`，由宿主把 `isOpen` 设回 `false`。

<CodeBlock code={basicUsage} language="typescript" />

<Callout type="info" title="覆盖层渲染在哪里">
  React 和 Vue 播放器会把覆盖层移到 `document.body` 末尾，而 `rk-stories-overlay` 就渲染在你放置它的位置，并用 `position: fixed` 铺满屏幕。不要把它放在带有 `transform`、`perspective`、`filter` 或 `will-change: transform` 的祖先元素里：这样的祖先会成为覆盖层的包含块，播放器的尺寸会跟随它而不是视口，并被它的 `overflow` 裁剪。创建了自身层叠上下文的祖先，也会限制 `--rk-stories-overlay-z` 能把播放器抬到多高。反过来，设置在任意祖先上的 `--rk-stories-*` 令牌都能作用到播放器。
</Callout>

## URL 状态 [#url-state]

<DemoLink href="https://angular-demo.reelkit.dev/stories-player-url?utm_source=docs">查看在线演示 →</DemoLink>

`RkStoriesUrlOverlayComponent` 是一个独立组件，它的打开状态存放在地址栏里。两个轴共用一个参数 —— `?story=<group>.<story>` —— 因此正在播放的故事有一个可分享、可收藏、可用后退按钮关闭的链接。用 `createOverlayUrlState` 和 `urlIndexTwoAxisKey` 创建控制器，然后作为 `controller` 传入。

<Callout type="info" title="内置 key">
  故事是双轴的，所以要把双轴 key 展开到控制器里：`urlIndexTwoAxisKey`（按位置定位用户和故事）或 `urlStableIdTwoAxisKey`（用户按稳定 `id` 定位）—— 两者都从 `@reelkit/angular-stories-player` 重新导出。参见 [URL 状态指南](/docs/core/guide#url-state)和 [Core API](/docs/core/api#url-state)。
</Callout>

<CodeBlock code={urlState} language="typescript" />

- 打开会压入**一条**历史记录。在故事之间移动*以及*切换用户都只是**替换**它，因此 N 次导航不会新增记录，一次后退始终关闭播放器。后退是关闭，而不是回到上一条故事。
- **内层导航也会写进 URL。** 在同一用户的故事间前进会把 `?story=2.`*n* 更新掉，因此深层链接能落到确切的那条故事。
- 只有当播放器是在应用内部打开时，后退才会关闭它 —— 那次跳转压入了一条记录。直接在新标签页打开的分享链接背后没有历史记录，后退会离开站点；✕ 按钮或 Escape 会就地移除参数并留在页面上。
- 指向不存在的用户或故事的参数 —— 过期书签、手改的值、超出该用户故事数量的序号 —— 会从 URL 中移除，而不是打开相邻的一条。
- 使用路由的应用应该传入基于路由器的适配器，让路由器始终是导航状态的唯一来源。`@reelkit/angular/ng-router-url-adapter` 中的 `createRouterUrlAdapter` 就是 Angular 路由器的现成适配器；绕过路由器直接写历史会让它的 location 过期，下一次导航就会丢掉参数。

**稳定链接。** 用户默认按位置定位，因此收藏的 `?story=2.0` 在信息流重新排序后会打开另一个人。改用稳定 id 定位用户 —— `outerCodec` 负责把 id 写进 URL，`outerLocator` 负责找到它所在的位置。再传入 `innerCodec` 以及 `innerLocate`、`innerIdentify`，就能对分组内部的故事做同样的事；不传这三个，故事那一半仍然是分组内部的普通局部索引。

<CodeBlock code={urlState2} language="typescript" />

**无限信息流。** 分页属于 `outerLocator` 的职责，与编解码器无关。`locate` 是同步的，只能回答已加载的分组 —— 指向第 400 个分组、而只加载了 20 个的分享链接会落空。`locateAsync` 是兜底，只在 `locate` 未命中时调用；故事随后会按最终落到的那个分组重新约束。

<Callout type="info" title="同一个 locateAsync，外层轴">
  这与单轴 key 接受的 `locateAsync` 分页器是同一个 —— 在双轴 key 上它跟着你传入的 `outerLocator` 走，因此分页发生在用户这一轴，而故事仍是已解析分组内部的局部索引。
</Callout>

<CodeBlock code={urlState3} language="typescript" />

- 在 `locateAsync` 等待期间，播放器保持关闭且参数原样保留，因此深层链接能熬过这次请求。返回 `null` 或拒绝则会移除参数。
- 如果答复在 URL 已经变化之后、关闭之后或卸载之后才到达，就会被丢弃 —— 一次缓慢的请求无法打开没人再要求的故事。
- `createOverlayUrlState` 的完整选项见 [Angular API 参考](/docs/angular/api#createoverlayurlstate)，逐步讲解见 [Angular 指南](/docs/angular/guide#url-state)。

## 记住看过的内容 [#remembering-what-was-seen]

在一个分组被完整看完之前，圆环会显示渐变；分组重新打开时，会停在观看者尚未看过的第一条 Story。两者都来自同一个 `createStoriesViewedStateController`：在信息流所在的地方创建一次，再作为 `viewed` 交给圆环列表和播放器，它们会自行读取存储、跟随其变化并记录展示过的内容。存储的条目按 id 指明作者和 Story，因此信息流重新排序后依然有效，同一个控制器在 React 和 Vue 中也能使用。

<CodeBlock code={rememberingWhatWasSeen} language="typescript" />

- **打开时的那条 Story 也算数。** 播放器打开时，屏幕上已有的那条 Story 会被报告为已看，所以打开一个只有一条 Story 的分组再关闭，它就会被标记为看完。
- **往后滑同样会续播。** `resumeStoryIndex` 对本次会话中第一次到达的每个分组生效，包括播放器打开时所在的那个，除非 `initialStoryIndex` 显式指定了 Story；已经滑过的分组会在离开处重新打开。显式传入的 `resumeStoryIndex` 输入优先于控制器的答案。
- **链接依然优先。** 使用 `rk-stories-url-overlay` 时，无论存储了什么，都由参数决定播放器在哪里打开。其他情况下由续播回调决定。
- **计数是位置，不是累计。** 条目记录的是到达过的最远那条 Story，因此给已看完的分组新增一条 Story 会让它的圆环重新亮起，从中间删掉一条则会让计数变短。
- **存储可插拔。** 传入 `storage: createSessionStorageAdapter()` 可在关闭标签页时遗忘，也可以传入你自己的 `StorageAdapter`。两个打开的标签页会通过浏览器的 storage 事件保持同步。
- **只在打开时才创建的播放器读取得太晚。** `rk-stories-overlay` 一存在就会读取存储，即使仍处于关闭状态，`rk-stories-ring-list` 也是如此。如果把浮层包在 `@if (open)` 里，它就没有这个时机：请在宿主的构造函数中调用 `attachViewedState(() => this.viewed)`，它会在宿主存活期间一直保持关联。相关选项以及它所基于的底层构件见 [Stories Core](/docs/stories-core#viewed-controller) 页面。

## 桌面轮播 [#desktop-carousel]

设置 `desktopLayout="carousel"`，播放器就会像 Instagram 网页版查看器那样布局：当前 Story 以正常尺寸留在中间，每侧最多各有两个相邻分组，以更小、压暗的卡片呈现。点击卡片会打开对应分组，切换分组时卡片会随之滑过。传入与圆环列表相同的 `viewed` 控制器，已看完分组的卡片就会显示灰色圆环。

<CodeBlock code={desktopCarousel} language="typescript" />

- **手机上仍是普通播放器。** 宽度不超过 768px 时不渲染卡片，滑动使用 `groupTransition`，与默认的 `'single'` 布局相同。跨过这个宽度调整窗口大小会实时切换。卡片显示时，分组是滑动而不是转动，无论 `groupTransition` 如何设置。
- **每张卡片预览分组将要打开的位置**：本次会话中离开时所在的 Story，否则是 `resumeStoryIndex` 返回的 Story。卡片显示视频封面或图片。两者都没有的 Story（例如渐变背景上的文字 Story）会由你的 `rkStoriesSlide` 模板按播放器尺寸绘制后再缩小；没有封面的视频显示卡片背景。这个预览收到的是 `isActive: false`，其生命周期回调什么也不做，因此无法驱动屏幕上那条 Story 的计时器。幻灯片在创建时做的事情（例如播放或统计）请放在 `isActive` 判断之后。
- **计时器会等幻灯片。** 在卡片移动结束之前，Story 不会启动计时器，也不会为它触发 `(storyViewed)`。
- **每种切换分组的方式都会滑动**：点击卡片、`StoriesApi.goToGroup`、`nextGroup` 和 `prevGroup`，以及越过分组末尾时的方向键。触摸滑动本身就在移动播放器，所以不会再叠加一次滑动。
- **重新设计卡片样式**用 `rkStoriesGroupPreview` 插槽，见[自定义轮播卡片](#custom-carousel-cards)。播放器仍然负责卡片的定位、缩放和滑动。

## 每个分组自带进度条和头部 [#chrome-placement]

默认情况下，播放器上方只有一个进度条和一个头部，分组切换完成后才换成新分组的内容。设置 `chromePlacement="group"` 后，每个分组都在自己的幻灯片里拥有一份，二者会像 Instagram 那样随分组一起转动。

<CodeBlock code={chromePlacement} language="typescript" />

- **相邻分组显示它停在哪里。** 播放器转向它时，它的进度条和头部显示它将打开的那个 Story，尚未播放任何部分。
- **正在离开的分组保持原样。** 它的进度条在转动结束前保留原有进度，所以一个已播完的分组会保持填满，而不会在转动中途清空。
- **屏幕上的每个分组都会渲染这些模板。** `rkStoriesProgressBar` 和 `rkStoriesHeader` 的上下文带有 `groupIndex` 和 `isActive`；对相邻分组，`isActive` 为 `false`，进度信号保持不变。
- **`rkStoriesHeader` 模板位于滑动区域内。** 点击它会切换 Story，除非点在 `button`、链接或带 `role="button"` 的元素上，所以其中的每个控件都应是这几类元素之一。
- **桌面端轮播在滑动过程中不受影响。** 卡片滑动时播放器是隐藏的，因此这个选项在分组打开后才会显现。

## 模板插槽 [#template-slots]

八个 `ng-template` 指令可以替换播放器的任意部分。每个都会收到带类型的上下文，其中每个值都有名字，与 React 和 Vue 插槽使用的名字相同，所以在头部插槽里 `let-author="author"` 能拿到作者。主值同时也是隐式值，所以只写 `let-author` 效果一样。没有提供的插槽会保留内置的呈现。

| 指令 | 类 | 上下文 | 说明 |
| --- | --- | --- | --- |
| `rkStoriesError` | `RkStoriesErrorDirective` | `{ $implicit: story, story, storyIndex, groupIndex }` | 替换内置的 "Content unavailable" 面板，绘制在当前 Story 之上 |
| `rkStoriesFooter` | `RkStoriesFooterDirective` | `{ $implicit: story, story, author, storyIndex }` | 在当前 Story 下方加一个页脚；播放器本身不绘制页脚 |
| `rkStoriesGroupPreview` | `RkStoriesGroupPreviewDirective` | `{ $implicit: group, group, groupIndex, story, offset, viewedCount, onOpen }` | 填充桌面轮播的卡片内容；定位、缩放和滑动仍由播放器负责 |
| `rkStoriesHeader` | `RkStoriesHeaderDirective` | `{ $implicit: author, author, story, storyIndex, isPaused, isMuted, isVideo, groupIndex, isActive, onToggleSound, onTogglePause, onClose }` | 替换默认头部（作者、暂停、声音、关闭）。使用 `chromePlacement="group"` 时它位于滑动区域内，参见[每个分组自带进度条和头部](/docs/angular-stories-player#chrome-placement)。 |
| `rkStoriesLoading` | `RkStoriesLoadingDirective` | `{ $implicit: story, story, storyIndex, groupIndex }` | 替换当前 Story 加载时头部显示的默认加载指示 |
| `rkStoriesNavigation` | `RkStoriesNavigationDirective` | `{ onPrevStory, onNextStory, onPrevGroup, onNextGroup, $implicit: { the same four } }` | 同时替换桌面端的两个箭头 |
| `rkStoriesProgressBar` | `RkStoriesProgressBarDirective` | `{ $implicit: group, group, totalStories, activeIndex, progress, groupIndex, isActive }` | 替换 canvas 进度条。`activeIndex` 和 `progress` 是内核信号，请用 `toAngularSignal` 桥接。 |
| `rkStoriesSlide` | `RkStoriesSlideDirective` | `{ $implicit: story, story, index, groupIndex, isActive, size, activeGroupIndex, activeStoryIndex, onDurationReady, onReady, onWaiting, onError, onEnded }` | 替换默认的图片与视频幻灯片 |

<CodeBlock code={templateSlots} language="typescript" />

`STORIES_TEMPLATE_SLOT_DIRECTIVES` 把八个类导出为一个数组，方便一次导入多个的组件使用。

每个插槽都通过播放器自身的注入器渲染，因此插槽里绘制的组件能解析到播放器的 provider——幻灯片模板中的 `rk-video-story-slide` 拿到的，正是头部按钮写入的那份声音状态。

### 自定义幻灯片 [#custom-slides]

<CodeBlock code={slideSlot} language="typescript" />

自定义幻灯片通过 `rkStoriesSlide` 上下文中的回调告诉播放器内容的状态。播放器只处理屏幕上那条 Story 的回调；其他幻灯片的调用会被忽略。

| 回调 | 时机 |
| --- | --- |
| `onReady` | 内容已就绪（图片加载完成、视频开始播放）。进度计时器开始，或等待轮播滑动结束后再开始。 |
| `onWaiting` | 内容卡住（视频播放中途缓冲）。显示加载圈，计时器暂停。 |
| `onError` | 内容加载失败。显示错误面板，计时器暂停。 |
| `onDurationReady` | 以毫秒报告媒体的真实时长（例如从视频元数据中读取），让计时器与之匹配。Story 上设置的 `duration` 优先于它。 |
| `onEnded` | 媒体自行播放结束，例如视频播到了结尾。播放器不等计时器，直接进入下一条 Story。 |

`rk-image-story-slide` 会发出 `(loaded)` 和 `(failed)`，`rk-video-story-slide` 会发出 `(playbackStarted)`、`(buffering)`、`(failed)`、`(durationReady)` 和 `(finished)`，因此包裹它们的幻灯片模板只需把每个事件转交给对应的回调。

<Callout type="info" title="预加载缓存">
  内置的 `RkImageStorySlideComponent` 和 `RkVideoStorySlideComponent` 会在后台预加载下一条 Story。观众翻到已预加载的 Story 时，内容立即出现，不会有加载指示。失败过一次的 URL 也会被记住，所以重新打开损坏的 Story 会直接显示错误，而不是再试一次。
</Callout>

## RkStoriesOverlayComponent 输出 [#rkstoriesoverlaycomponent-outputs]

| 输出 | 负载 | 说明 |
| --- | --- | --- |
| `(apiReady)` | `StoriesApi` | 播放器可以接受指令时发出，此后每次打开都会再次发出 |
| `(closed)` | `void` | 观众关闭播放器时发出。播放器本身不动，由宿主决定。在 `rk-stories-url-overlay` 中，此时参数已被清除。 |
| `(doubleTapped)` | `{ groupIndex, storyIndex }` | 双击时发出，同时播放爱心动画 |
| `(groupChanged)` | `number` | 当前分组改变后发出 |
| `(paused)` | `void` | 长按或点击头部暂停按钮时发出 |
| `(resumed)` | `void` | 松开或点击头部播放按钮时发出 |
| `(storyChanged)` | `{ groupIndex, storyIndex }` | 当前 Story 改变后发出 |
| `(storyCompleted)` | `{ groupIndex, storyIndex }` | 某条 Story 的计时器走完时发出 |
| `(storyViewed)` | `{ groupIndex, storyIndex }` | Story 出现在屏幕上时发出，包括打开时的第一条 |

## 无障碍 [#accessibility]

浮层根元素是一个模态对话框（`role="dialog"`、`aria-modal="true"`）。设置 `ariaLabel` 可以改变屏幕阅读器的朗读内容，默认是 "Stories player"。

浮层在打开时接管焦点，关闭时把焦点还给触发它的元素。Tab 与 Shift+Tab 在内部可聚焦元素之间循环，并在两端回绕；跑出去的焦点（点击外部、程序化聚焦）会被拉回来。播放器打开期间 body 滚动保持锁定。实现使用 `@reelkit/core` 的 `captureFocusForReturn` 与 `createFocusTrap`，并由 `@reelkit/angular` 重新导出。

在桌面轮播中，每张默认卡片都是一个按钮，标签为 "Open stories by" 加作者名。卡片在 Tab 顺序中排在播放器控件之后，并在滑动进行时移出 Tab 顺序；打开自己分组的那张卡片会把焦点交还给对话框，而不是丢在页面上。

## 服务端渲染 [#server-side-rendering]

播放器在打开之前不渲染任何内容，构造期间也不读取任何浏览器 API，因此在 Angular SSR 下是安全的。已看状态在挂载之后读取，而不是在渲染过程中读取，这正是服务端渲染与首次客户端渲染保持一致的原因。

## 键盘快捷键 [#keyboard-shortcuts]

| 按键 | 操作 |
| --- | --- |
| `ArrowLeft` | 上一条 Story。在分组的第一条 Story 上时，打开上一个分组，停在离开时的位置；在第一个分组上什么也不做。 |
| `ArrowRight` | 下一条 Story。在分组的最后一条 Story 上时，打开下一个分组；在最后一个分组上则关闭播放器。 |
| `Escape` | 关闭播放器 |
