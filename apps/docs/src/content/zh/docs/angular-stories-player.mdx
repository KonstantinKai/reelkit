## URL 状态 [#url-state]

<DemoLink href="https://angular-demo.reelkit.dev/stories-player-url?utm_source=docs">查看在线演示 →</DemoLink>

`RkStoriesUrlOverlayComponent` 是一个独立组件，它的打开状态存放在地址栏里。两个轴共用一个参数 —— `?story=<group>.<story>` —— 因此正在播放的故事有一个可分享、可收藏、可用后退按钮关闭的链接。用 `createOverlayUrlState` 和 `urlIndexTwoAxisKey` 创建控制器，然后作为 `controller` 传入。

<Callout type="info" title="内置 key">
  故事是双轴的，所以要把双轴 key 展开到控制器里：`urlIndexTwoAxisKey`（按位置定位用户和故事）或 `urlStableIdTwoAxisKey`（用户按稳定 `id` 定位）—— 两者都从 `@reelkit/angular-stories-player` 重新导出。参见 [URL 状态指南](/docs/core/guide#url-state)和 [Core API](/docs/core/api#url-state)。
</Callout>

<CodeBlock code={urlState} language="typescript" />

- 打开会压入**一条**历史记录。在故事之间移动*以及*切换用户都只是**替换**它，因此 N 次导航不会新增记录，一次后退始终关闭播放器。后退是关闭，而不是回到上一条故事。
- **内层导航也会写进 URL。** 在同一用户的故事间前进会把 `?story=2.`*n* 更新掉，因此深层链接能落到确切的那条故事。
- 只有当播放器是在应用内部打开时，后退才会关闭它 —— 那次跳转压入了一条记录。直接在新标签页打开的分享链接背后没有历史记录，后退会离开站点；✕ 按钮或 Escape 会就地移除参数并留在页面上。
- 指向不存在的用户或故事的参数 —— 过期书签、手改的值、超出该用户故事数量的序号 —— 会从 URL 中移除，而不是打开相邻的一条。
- 使用路由的应用应该传入基于路由器的适配器，让路由器始终是导航状态的唯一来源。`@reelkit/angular/ng-router-url-adapter` 中的 `createRouterUrlAdapter` 就是 Angular 路由器的现成适配器；绕过路由器直接写历史会让它的 location 过期，下一次导航就会丢掉参数。

**稳定链接。** 用户默认按位置定位，因此收藏的 `?story=2.0` 在信息流重新排序后会打开另一个人。改用稳定 id 定位用户 —— `outerCodec` 负责把 id 写进 URL，`outerLocator` 负责找到它所在的位置。再传入 `innerCodec` 以及 `innerLocate`、`innerIdentify`，就能对分组内部的故事做同样的事；不传这三个，故事那一半仍然是分组内部的普通局部索引。

<CodeBlock code={urlState2} language="typescript" />

**无限信息流。** 分页属于 `outerLocator` 的职责，与编解码器无关。`locate` 是同步的，只能回答已加载的分组 —— 指向第 400 个分组、而只加载了 20 个的分享链接会落空。`locateAsync` 是兜底，只在 `locate` 未命中时调用；故事随后会按最终落到的那个分组重新约束。

<Callout type="info" title="同一个 locateAsync，外层轴">
  这与单轴 key 接受的 `locateAsync` 分页器是同一个 —— 在双轴 key 上它跟着你传入的 `outerLocator` 走，因此分页发生在用户这一轴，而故事仍是已解析分组内部的局部索引。
</Callout>

<CodeBlock code={urlState3} language="typescript" />

- 在 `locateAsync` 等待期间，播放器保持关闭且参数原样保留，因此深层链接能熬过这次请求。返回 `null` 或拒绝则会移除参数。
- 如果答复在 URL 已经变化之后、关闭之后或卸载之后才到达，就会被丢弃 —— 一次缓慢的请求无法打开没人再要求的故事。
- `createOverlayUrlState` 的完整选项见 [Angular API 参考](/docs/angular/api#createoverlayurlstate)，逐步讲解见 [Angular 指南](/docs/angular/guide#url-state)。

## 每个分组自带进度条和头部 [#chrome-placement]

默认情况下，播放器上方只有一个进度条和一个头部，分组切换完成后才换成新分组的内容。设置 `chromePlacement="group"` 后，每个分组都在自己的幻灯片里拥有一份，二者会像 Instagram 那样随分组一起转动。

<CodeBlock code={chromePlacement} language="typescript" />

- **相邻分组显示它停在哪里。** 播放器转向它时，它的进度条和头部显示它将打开的那个 Story，尚未播放任何部分。
- **正在离开的分组保持原样。** 它的进度条在转动结束前保留原有进度，所以一个已播完的分组会保持填满，而不会在转动中途清空。
- **屏幕上的每个分组都会渲染这些模板。** `rkStoriesProgressBar` 和 `rkStoriesHeader` 的上下文带有 `groupIndex` 和 `isActive`；对相邻分组，`isActive` 为 `false`，进度信号保持不变。
- **`rkStoriesHeader` 模板位于滑动区域内。** 点击它会切换 Story，除非点在 `button`、链接或带 `role="button"` 的元素上，所以其中的每个控件都应是这几类元素之一。
- **桌面端轮播在滑动过程中不受影响。** 卡片滑动时播放器是隐藏的，因此这个选项在分组打开后才会显现。

## 模板插槽 [#template-slots]

八个 `ng-template` 指令可以替换播放器的任意部分。每个都会收到带类型的上下文，其中最常用的值作为隐式值——所以在头部插槽里，`let-author` 无需具名就能拿到作者。没有提供的插槽会保留内置的呈现。

| 指令 | 类 | 上下文 | 说明 |
| --- | --- | --- | --- |
| `rkStoriesError` | `RkStoriesErrorDirective` | `{ $implicit: story, storyIndex, groupIndex }` | 替换内置的 "Content unavailable" 面板，绘制在当前 Story 之上 |
| `rkStoriesFooter` | `RkStoriesFooterDirective` | `{ $implicit: story, author, storyIndex }` | 在当前 Story 下方加一个页脚；播放器本身不绘制页脚 |
| `rkStoriesGroupPreview` | `RkStoriesGroupPreviewDirective` | `{ $implicit: group, groupIndex, story, offset, viewedCount, onOpen }` | 填充桌面轮播的卡片内容；定位、缩放和滑动仍由播放器负责 |
| `rkStoriesHeader` | `RkStoriesHeaderDirective` | `{ $implicit: author, story, storyIndex, isPaused, isMuted, isVideo, groupIndex, isActive, onToggleSound, onTogglePause, onClose }` | 替换默认头部（作者、暂停、声音、关闭）。使用 `chromePlacement="group"` 时它位于滑动区域内，参见[每个分组自带进度条和头部](/docs/angular-stories-player#chrome-placement)。 |
| `rkStoriesLoading` | `RkStoriesLoadingDirective` | `{ $implicit: story, storyIndex, groupIndex }` | 替换当前 Story 加载时头部显示的默认加载指示 |
| `rkStoriesNavigation` | `RkStoriesNavigationDirective` | `{ $implicit: { onPrevStory, onNextStory, onPrevGroup, onNextGroup } }` | 同时替换桌面端的两个箭头 |
| `rkStoriesProgressBar` | `RkStoriesProgressBarDirective` | `{ $implicit: group, totalStories, activeIndex, progress, groupIndex, isActive }` | 替换 canvas 进度条。`activeIndex` 和 `progress` 是内核信号，请用 `toAngularSignal` 桥接。 |
| `rkStoriesSlide` | `RkStoriesSlideDirective` | `{ $implicit: story, index, groupIndex, isActive, size, activeGroupIndex, activeStoryIndex, onDurationReady, onReady, onWaiting, onError, onEnded }` | 替换默认的图片与视频幻灯片 |

<CodeBlock code={templateSlots} language="typescript" />

`STORIES_TEMPLATE_SLOT_DIRECTIVES` 把八个类导出为一个数组，方便一次导入多个的组件使用。

每个插槽都通过播放器自身的注入器渲染，因此插槽里绘制的组件能解析到播放器的 provider——幻灯片模板中的 `rk-video-story-slide` 拿到的，正是头部按钮写入的那份声音状态。

## 子组件 [#sub-components]

导出的构件，可以在插槽内组合，也可以单独使用。

| 组件 | 是什么 |
| --- | --- |
| `RkCanvasProgressBarComponent` | 直接由计时器信号绘制的 canvas 分段进度条。分组内 Story 很多时会处理滑动窗口。传入 `[live]="false"` 时只在信号变化和尺寸改变后重绘，没有动画循环。 |
| `RkHeartAnimationComponent` | 双击的爱心。动画结束时发出 `(completed)`，父组件据此移除它。 |
| `RkImageStorySlideComponent` | 使用 `object-fit: cover` 的整屏图片幻灯片，通过 output 上报加载与错误。 |
| `RkStoriesRingComponent` | 带渐变圆环的圆形头像。两种状态：还有未看内容时旋转，全部看完后变为平直。发出 `(clicked)`。 |
| `RkStoriesRingListComponent` | 带作者名的横向圆环列表，每个分组一个。发出 `(selected)` 并带上分组索引。 |
| `RkStoryHeaderComponent` | 默认头部：头像、名称、认证标识、相对时间、暂停、声音、关闭以及加载指示。 |
| `RkVideoStorySlideComponent` | 基于唯一共享 `<video>` 元素的视频幻灯片，用于在 iOS 上保持声音连续。处理自动播放、封面帧与时长上报。 |

| `initialStoryIndex` | `number` | 续播位置，否则 `0` | 播放器打开时所在 Story 的索引（从 0 开始）。显式指定会覆盖任何记住的位置；不指定时，首个分组与其他分组一样按续播位置打开。 |
| `innerTransitionDuration` | `number` | `200` | 同一位作者的 Story 之间淡入淡出的时长，单位毫秒 |
| `isOpen` | `boolean` | `false` | 为 true 时渲染播放器并锁定 body 滚动 |
| `minSegmentWidth` | `number` | `8` | 进度分段的最小宽度，低于此值进度条会改为滚动一个分段窗口，单位像素 |
| `resumeStoryIndex` | `(groupIndex: number) => number` | — | 首次到达某个分组时从哪条 Story 打开。只对本次打开期间尚未访问过的分组询问，且优先于 `viewed`。 |
| `tapZoneSplit` | `number` | `0.3` | 点击区域的分割比例（0–1）。左侧后退，其余前进。 |
| `viewed` | `StoriesViewedStateController` | — | 观众已看过的内容，来自 `createStoriesViewedStateController()`。分组从第一条未看的 Story 续播，每条展示过的 Story 都会记录，看完的分组在轮播卡片上圆环会变暗。请把同一个控制器也交给 `rk-stories-ring-list`。 |

每个插槽还有对应的输入，供自己持有 `TemplateRef` 而非投影它的组件使用：`slideTemplate`、`headerTemplate`、`footerTemplate`、`progressBarTemplate`、`navigationTemplate`、`loadingTemplate`、`errorTemplate` 和 `groupPreviewTemplate`。以这种方式指定的模板优先于投影进播放器的模板。

## 无障碍 [#accessibility]

浮层根元素是一个模态对话框（`role="dialog"`、`aria-modal="true"`）。设置 `ariaLabel` 可以改变屏幕阅读器的朗读内容，默认是 "Stories player"。

浮层在打开时接管焦点，关闭时把焦点还给触发它的元素。Tab 与 Shift+Tab 在内部可聚焦元素之间循环，并在两端回绕；跑出去的焦点（点击外部、程序化聚焦）会被拉回来。播放器打开期间 body 滚动保持锁定。实现使用 `@reelkit/angular` 的 `captureFocusForReturn` 与 `createFocusTrap`。

在桌面轮播中，每张默认卡片都是一个按钮，标签为 "Open stories by" 加作者名。卡片在 Tab 顺序中排在播放器控件之后，并在滑动进行时移出 Tab 顺序。

## 服务端渲染 [#server-side-rendering]

播放器在打开之前不渲染任何内容，构造期间也不读取任何浏览器 API，因此在 Angular SSR 下是安全的。已看状态在挂载之后读取，而不是在渲染过程中读取，这正是服务端渲染与首次客户端渲染保持一致的原因。
